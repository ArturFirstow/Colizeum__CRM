# Заливаем Colizeum Agency на боевой сервер

Инструкция подходит для любого VPS с Ubuntu 22.04/24.04 — Beget, AdminVPS,
Timeweb и прочие. Домен может быть у того же хостера или у другого регистратора.
Ниже — по шагам, от начала до момента, когда сайт открывается в обычном браузере
по адресу `https://ваш-домен.ru`.

> **Сервер уже поднят руками?** Пропустите установку и переходите сразу к разделу
> [«Обновление уже работающего сервера»](#обновление-уже-работающего-сервера) в конце.

Что получится в итоге:

```
Браузер → ваш-домен.ru (HTTPS) → nginx на сервере → Next.js на порту 3000 → SQLite + папка storage
```

**Сколько времени:** 40–60 минут, если всё под рукой.

---

## Шаг 0. Что приготовить перед началом

Соберите в блокнот четыре вещи:

| Что | Где взять |
|---|---|
| **IP-адрес сервера** (вида `95.163.___.___`) | письмо от AdminVPS или панель AdminVPS |
| **Пароль root** от сервера | оттуда же |
| **Имя домена** (например `crm.colizeum-agency.ru`) | панель Timeweb |
| **Токен GitHub** | github.com → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token, галочка `repo` |

Токен нужен один раз — чтобы сервер смог скачать код из приватного репозитория.
Это длинная строка вида `ghp_xxxxxxxx`. Никому её не показывайте.

---

## Шаг 1. Домен в Timeweb → на сервер

Это единственный шаг, который делается **не** на сервере, и он самый долгий по
времени ожидания — поэтому делаем его первым, пока настраиваем всё остальное.

1. Зайдите в панель Timeweb → раздел **«Домены»** → ваш домен → **«DNS-записи»**
   (или «Настройка DNS»).
2. Удалите/замените существующие записи типа **A** для `@` и `www`.
3. Добавьте две записи:

| Тип | Имя (субдомен) | Значение |
|---|---|---|
| A | `@` (или пусто) | IP-адрес вашего сервера |
| A | `www` | IP-адрес вашего сервера |

> Если хотите отдельный адрес вида `crm.colizeum-agency.ru`, а основной сайт
> оставить как есть — добавьте одну запись: тип **A**, имя `crm`, значение — IP сервера.

4. Сохраните. Обновление DNS занимает от 10 минут до нескольких часов
   (обычно ~15 минут).

**Как проверить, что сработало.** На своём компьютере откройте PowerShell
(Win + R → `powershell` → Enter) и выполните:

```powershell
nslookup ваш-домен.ru
```

В ответе должен быть IP вашего сервера. Пока там не он — HTTPS на шаге 8 не
получится, но шаги 2–7 можно спокойно делать параллельно.

## Шаг 2. Подключаемся к серверу

На Windows откройте **PowerShell** и выполните (подставьте свой IP):

```powershell
ssh root@95.163.000.000
```

- Первый раз спросит `Are you sure you want to continue connecting?` → напечатайте `yes` → Enter.
- Спросит пароль → вставьте пароль root. **Пароль при вводе не отображается —
  это нормально**, просто вставьте (правой кнопкой мыши) и нажмите Enter.

Если видите строку вида `root@vps12345:~#` — вы внутри сервера. Дальше все
команды выполняются здесь.

## Шаг 3. Скачиваем код на сервер

Подставьте свой токен GitHub вместо `ВАШ_ТОКЕН` и нужную ветку вместо `main`:

```bash
apt-get update -y && apt-get install -y git
mkdir -p /var/www && cd /var/www
git clone -b main https://ВАШ_ТОКЕН@github.com/ArturFirstow/Colizeum__CRM.git colizeum
cd colizeum
ls
```

Последняя команда должна показать `package.json`, `src`, `prisma`, `deploy`.
Если показала — код на сервере.

---

## Шаг 4. Настраиваем сервер одной командой

Скрипт поставит Node.js 22, nginx, pm2, certbot и настроит файрвол:

```bash
bash /var/www/colizeum/deploy/setup-server.sh
```

Идёт 3–7 минут, много текста — это нормально. В конце должно быть
`Готово. Папка проекта: /var/www/colizeum`.

---

## Шаг 5. Настройки (.env)

Создаём файл с настройками из образца:

```bash
cd /var/www/colizeum
cp deploy/env.production.example .env
```

Генерируем секрет для входа в систему:

```bash
openssl rand -base64 32
```

Скопируйте получившуюся строку. Открываем файл настроек:

```bash
nano .env
```

Что поправить:

1. `AUTH_SECRET="..."` — вставьте сюда скопированную строку.
2. `SEED_PW_FIRSTOV="..."` и остальные `SEED_PW_*` — придумайте пароли сотрудникам
   (можно одинаковые на старте, потом поменяете). Это пароли для входа в CRM.
3. `AI_API_KEY=""` — если ключ ИИ уже есть, вставьте; если нет — оставьте пустым,
   сервис работает и без него.

Сохранить и выйти из nano: **Ctrl + O** → Enter → **Ctrl + X**.

## Шаг 6. Устанавливаем, создаём базу, собираем

По очереди (каждую команду дождаться до конца):

```bash
cd /var/www/colizeum
mkdir -p data storage
npm ci
npx prisma db push
```

Теперь **первое и единственное** заполнение базы — создаст сотрудников и демо-данные:

```bash
npx prisma db seed
```

> ⚠️ Эту команду больше НИКОГДА не запускайте на боевом сервере — она стирает
> базу и заливает демо-набор заново. Все дальнейшие обновления идут через
> `deploy/update.sh`, который сид не трогает.

Собираем рабочую версию сайта:

```bash
npm run build
```

Займёт 2–5 минут. В конце должно быть `✓ Compiled successfully` и таблица страниц.

---

## Шаг 7. Запускаем сервис

```bash
cd /var/www/colizeum
pm2 start deploy/ecosystem.config.cjs
pm2 save
```

Проверяем, что он живой:

```bash
pm2 status
curl -I http://127.0.0.1:3000
```

`pm2 status` должен показать `colizeum` со статусом **online**, а `curl` — строку
`HTTP/1.1 200 OK` (или `307` — тоже нормально, это редирект на страницу входа).

Если статус `errored` — смотрим причину: `pm2 logs colizeum --lines 50`.

---

## Шаг 8. Nginx — чтобы сайт открывался по домену

Подставьте свой домен вместо `ваш-домен.ru` (в обеих командах):

```bash
sed 's/DOMAIN/ваш-домен.ru/g' /var/www/colizeum/deploy/nginx.conf.template \
  > /etc/nginx/sites-available/colizeum
ln -sf /etc/nginx/sites-available/colizeum /etc/nginx/sites-enabled/colizeum
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

`nginx -t` должен ответить `syntax is ok` / `test is successful`.

**Промежуточная проверка:** откройте в браузере `http://ваш-домен.ru` (пока без
буквы `s`). Должна появиться страница входа Colizeum. Если появилась — самое
сложное позади.

---

## Шаг 9. Включаем HTTPS (замочек в браузере)

Обязательный шаг: без HTTPS вход в систему не заработает — cookie сессии
выдаётся только по защищённому соединению.

```bash
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

Certbot задаст три вопроса:

1. **Email** — ваша почта (для писем об истечении сертификата).
2. **Agree to terms** — напечатайте `Y`.
3. **Share email with EFF** — можно `N`.
4. Если спросит про редирект — выберите **2 (Redirect)**, чтобы `http` сам
   переводил на `https`.

В конце: `Congratulations! You have successfully enabled HTTPS`.

Сертификат продлевается автоматически. Проверить механизм продления:

```bash
certbot renew --dry-run
```

> Если certbot ругается `DNS problem` / `Timeout during connect` — значит домен
> ещё не «доехал» до сервера (шаг 1). Подождите 15–30 минут и повторите команду.

## Шаг 10. Проверяем в настоящем браузере

Откройте `https://ваш-домен.ru`

1. В адресной строке — замочек, страница входа Colizeum с жёлто-графитовым брендингом.
2. Логин: `a.firstov@colizeum.ru`, пароль — тот, что вы задали в `SEED_PW_FIRSTOV`.
3. После входа должен открыться раздел «Сегодня» со всеми пунктами меню слева.
4. Пройдитесь по нескольким разделам: «Клиенты», «Документы», «Оплаты»,
   «Мессенджер» — всё должно открываться.
5. Проверьте загрузку файла в любой карточке — файл должен загрузиться и скачаться обратно.

**Готово — сайт в интернете.**

## После запуска: что нужно знать

### Обновить сайт (когда появились новые правки в коде)

```bash
bash /var/www/colizeum/deploy/update.sh
```

Скрипт сам сделает копию базы, заберёт новый код, пересоберёт и перезапустит.
Данные не пострадают.

Если проект лежит по другому пути — укажите его:

```bash
APP_DIR=/root/Colizeum__CRM bash /root/Colizeum__CRM/deploy/update.sh
```

### Проверить сервер целиком

```bash
bash /var/www/colizeum/deploy/healthcheck.sh
```

За один заход проверяет: работает ли приложение, не остался ли `AUTH_SECRET` из
примера, на месте ли база и файлы, свежие ли резервные копии, жив ли сертификат и
его автопродление, включён ли файрвол, сколько места на диске. Ничего не меняет —
только показывает, что требует внимания.

### Включить ежедневные резервные копии

```bash
apt-get install -y sqlite3
crontab -e
```

(если спросит редактор — выберите `1` — nano). В конец файла добавьте строку:

```
0 3 * * * bash /var/www/colizeum/deploy/backup.sh >> /var/log/colizeum-backup.log 2>&1
```

Сохранить: Ctrl + O → Enter → Ctrl + X. Теперь каждую ночь в 3:00 база и файлы
копируются в `/var/backups/colizeum`, хранятся последние 14 копий.

Скачать копию на свой компьютер (выполняется **на компьютере**, не на сервере):

```powershell
scp root@95.163.000.000:/var/backups/colizeum/db_*.db C:\Users\Colizeum\Downloads\
```

### Полезные команды

| Что нужно | Команда |
|---|---|
| Посмотреть, работает ли сервис | `pm2 status` |
| Посмотреть ошибки | `pm2 logs colizeum --lines 100` |
| Перезапустить сервис | `pm2 restart colizeum` |
| Перезапустить nginx | `systemctl reload nginx` |
| Проверить сертификат | `certbot certificates` |
| Место на диске | `df -h` |

### Если что-то сломалось

| Симптом | Что делать |
|---|---|
| Браузер: «502 Bad Gateway» | Сервис упал. `pm2 status` → `pm2 restart colizeum` → `pm2 logs colizeum` |
| Браузер: «Сайт не найден» / бесконечная загрузка | DNS ещё не обновился или файрвол. `nslookup ваш-домен.ru`, `ufw status` |
| Вход не работает, страницу перекидывает обратно | Не включён HTTPS (шаг 9) или пустой `AUTH_SECRET` в `.env` |
| Файлы не загружаются, ошибка 413 | В nginx-конфиге потерялся `client_max_body_size 60m` — вернуть и `systemctl reload nginx` |
| ИИ-напарник отвечает ошибкой | Ключ/провайдер в `.env`. Проверить: `cd /var/www/colizeum && npm run ai:check` |

### Про базу данных

Сейчас используется SQLite — один файл `/var/www/colizeum/data/prod.db`. Для
команды из 5 человек этого достаточно с большим запасом, и это сильно проще в
обслуживании. Переезд на PostgreSQL понадобится, только если появится второй
сервер или счёт пользователей пойдёт на сотни — код к этому готов
(`prisma/schema.prisma`, меняется провайдер датасорса).

### Безопасность (сделать в первую неделю)

1. Сменить пароли сотрудников из раздела «Команда» внутри сервиса.
2. Настроить вход на сервер по ключу вместо пароля (можно попросить помощи).
3. Убедиться, что файл `.env` не попал в git: `git status` не должен его показывать.

## Обновление уже работающего сервера

Если сервер настраивали вручную (или инструкцией выше, но давно), а в коде с тех
пор появились правки — порядок такой. Подставьте свой путь к проекту вместо
`/var/www/colizeum`.

```bash
cd /var/www/colizeum
git pull
npm ci
npx prisma db push        # добавляет новые поля, ДАННЫЕ СОХРАНЯЮТСЯ
npm run build
pm2 restart colizeum
```

⚠️ **Не запускайте `npm run setup` на боевом сервере.** Внутри него сид, а сид
стирает базу и заливает демо-данные заново. Только `npx prisma db push`.

### Разовые действия после конкретных обновлений

**Блокер стал флажком** (обновление 08.2026). Один раз выполните:

```bash
npx tsx scripts/backfill-blocker-flag.ts
```

Скрипт поднимет флажок у сделок, где причина блокера действительно записана, и
уберёт «пустые» блокеры — из-за них сделки висели заблокированными навсегда.

### Обязательная проверка безопасности

Откройте `.env` и убедитесь, что `AUTH_SECRET` — ваша собственная строка, а не
`change-me-please-generate-a-long-random-secret-string` из примера. Этот текст
лежит в репозитории: зная его, посторонний может подделать cookie и войти в
сервис под любым сотрудником.

```bash
grep AUTH_SECRET /var/www/colizeum/.env
```

Если там значение из примера — замените:

```bash
openssl rand -base64 32          # скопируйте результат в .env
pm2 restart colizeum
```

Начиная с версии 08.2026 приложение с таким секретом на проде просто не
запустится — специально, чтобы это нельзя было пропустить.

### Стоит ли переходить на PostgreSQL

Пока — нет. Для команды из пяти человек SQLite быстрее, надёжнее в обслуживании
и резервируется копированием одного файла. PostgreSQL на VPS с 2 ГБ памяти
отъест часть ресурсов, которые нужны сборке Next.js.

Переходить имеет смысл, когда появится второй сервер приложения, счёт
одновременных пользователей пойдёт на десятки или потребуется репликация. Код к
этому готов: в `prisma/schema.prisma` меняется `provider` датасорса на
`postgresql`, в `.env` — `DATABASE_URL`, дальше `npx prisma db push` и перенос
данных.
