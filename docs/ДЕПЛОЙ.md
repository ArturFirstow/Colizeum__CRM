# Запуск сервиса на домене

Пошаговая инструкция: от пустого сервера до работающего сайта на вашем домене.
Рассчитана на человека без опыта администрирования. Всё, что нужно, —
копировать команды по одной и читать, что отвечает сервер.

Времени займёт около часа. Делать всё за один присест не обязательно.

---

## Почему именно обычный сервер, а не Vercel

Сервис хранит базу в файле рядом с собой, загруженные документы — на диске,
а мгновенный чат держит подключения в памяти процесса. «Облака без сервера»
(Vercel, Netlify) после каждого запроса поднимают новую копию приложения с
чистого листа — база и все загруженные файлы там будут пропадать.

Поэтому нужен **обычный VPS** — виртуальный сервер с постоянным диском.
Это и проще, и дешевле.

## Почему сервер лучше брать российский

1. **Скорость для сотрудников.** Все в России, сервер рядом — интерфейс
   отзывчивый.
2. **ИИ работает.** DeepSeek из российских дата-центров доступен, проверено.
3. **Персональные данные.** В сервисе лежат имена и почты сотрудников и
   контакты клиентов. По российскому закону такие данные должны храниться на
   серверах в России. Это не юридическая консультация — но повод не выносить
   базу за рубеж без разговора с юристом.

Подойдут: **Timeweb Cloud**, **Selectel**, **Reg.ru**, **Yandex Cloud**.

## Шаг 1. Купить сервер

Берите самый простой тариф — сервису этого хватает с запасом:

| Параметр | Значение |
| --- | --- |
| Процессор | 2 ядра |
| Память | 4 ГБ |
| Диск | 40 ГБ SSD |
| Система | **Ubuntu 24.04** |

Цена — около 500–900 ₽ в месяц.

После оплаты хостинг пришлёт **IP-адрес** сервера и **пароль root**. Запишите
их, они понадобятся дальше.

---

## Шаг 2. Направить домен на сервер

В личном кабинете, где куплен домен, откройте настройки DNS и добавьте две
записи (если такие уже есть — исправьте их):

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | IP-адрес сервера |
| A | `www` | IP-адрес сервера |

Изменения расходятся по интернету от 10 минут до нескольких часов. Пока ждёте,
делайте следующие шаги — они от домена не зависят.

Проверить, дошло ли, можно в PowerShell на своём компьютере:

```powershell
nslookup ваш-домен.ru
```

Если в ответе виден IP вашего сервера — готово.

---

## Шаг 3. Подключиться к серверу

На своём компьютере откройте PowerShell и введите (подставьте свой IP):

```powershell
ssh root@123.45.67.89
```

Спросит про «continue connecting» — ответьте `yes`. Затем введите пароль
(при вводе пароль не отображается, это нормально — печатайте вслепую и жмите Enter).

Дальше все команды выполняются **на сервере**, в этом же окне.

---

## Шаг 4. Установить программы

Одной командой ставим всё необходимое: Node.js 22, git, веб-сервер nginx,
менеджер процессов pm2 и утилиту для бесплатного HTTPS.

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git nginx certbot python3-certbot-nginx sqlite3
npm install -g pm2
```

Проверяем, что Node встал:

```bash
node --version
```

Должно ответить `v22.` с чем-то.

---

## Шаг 5. Скачать проект

Репозиторий закрытый, поэтому нужен ключ доступа — **Personal Access Token**.

1. Откройте на своём компьютере github.com → аватар справа сверху → **Settings**
2. В самом низу слева → **Developer settings**
3. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
4. Название любое, срок — «No expiration», галочка **repo**
5. **Generate token** и сразу скопируйте строку `ghp_…` — второй раз её не покажут

Теперь на сервере:

```bash
mkdir -p /var/www && cd /var/www
git clone https://github.com/ArturFirstow/Colizeum__CRM.git colizeum
cd colizeum
git checkout claude/service-blueprint-frontend-ref797
```

Спросит логин — введите `ArturFirstow`. Спросит пароль — **вставьте токен**
`ghp_…`, а не пароль от GitHub.

Чтобы токен не спрашивали каждый раз:

```bash
git config --global credential.helper store
```

## Шаг 6. Настроить переменные окружения

```bash
cp .env.example .env
nano .env
```

Откроется простой текстовый редактор. Приведите файл к такому виду:

```
DATABASE_URL="file:./dev.db"
AUTH_SECRET="сюда-вставим-на-следующем-шаге"

STORAGE_DRIVER="local"
STORAGE_LOCAL_DIR="./storage"

AI_PROVIDER="deepseek"
AI_API_KEY="ваш-ключ-от-deepseek"
```

Сохранить и выйти: `Ctrl+O`, `Enter`, затем `Ctrl+X`.

Теперь сгенерируем секрет для входа в сервис (им подписываются сессии — если
его не поменять, чужой человек сможет подделать вход):

```bash
openssl rand -base64 32
```

Скопируйте выданную строку, снова откройте `nano .env` и вставьте её в
`AUTH_SECRET`. Сохраните.

## Шаг 7. Первый запуск

```bash
npm ci
npx prisma generate
npx prisma db push
```

Теперь **один раз** наполняем базу сотрудниками и демо-данными:

```bash
npx prisma db seed
```

> ⚠️ **Эту команду выполняют ровно один раз.** Она стирает базу и создаёт всё
> заново. Когда сервис уже работает с реальными данными, запуск сида сотрёт
> всю работу отдела. Для обновлений есть `npx prisma db push` — она добавляет
> новые поля и **сохраняет** данные.

Собираем и запускаем:

```bash
npm run build
pm2 start npm --name colizeum -- start
pm2 save
pm2 startup
```

Последняя команда напечатает ещё одну команду — скопируйте её и выполните.
Это нужно, чтобы сервис сам поднимался после перезагрузки сервера.

Проверяем, что живой:

```bash
curl -I http://127.0.0.1:3000
```

Должно ответить `HTTP/1.1 200 OK`.

## Шаг 8. Открыть сайт наружу

Настраиваем nginx — он принимает запросы из интернета и передаёт их сервису.

```bash
nano /etc/nginx/sites-available/colizeum
```

Вставьте это, заменив `ваш-домен.ru` на свой (в двух местах):

```nginx
server {
    listen 80;
    server_name ваш-домен.ru www.ваш-домен.ru;

    # Загрузка документов и презентаций — файлы бывают тяжёлые.
    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Мессенджер держит постоянное соединение, чтобы сообщения приходили
    # мгновенно. Без этих трёх строк nginx его буферизует и рвёт по таймауту.
    location /api/chat/stream {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 24h;
    }
}
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`) и включите:

```bash
ln -sf /etc/nginx/sites-available/colizeum /etc/nginx/sites-enabled/colizeum
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

`nginx -t` должен ответить `syntax is ok` и `test is successful`.

Откройте в браузере `http://ваш-домен.ru` — должна появиться страница входа.

---

## Шаг 9. Включить HTTPS (замочек в браузере)

```bash
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

Спросит почту (для писем об истечении сертификата) и согласие с условиями.
На вопрос про перенаправление выберите **2** — весь трафик на HTTPS.

Сертификат бесплатный и продлевается сам. Проверить, что автопродление
настроено:

```bash
systemctl status certbot.timer
```

Теперь сайт открывается по `https://ваш-домен.ru`.

cd /var/www/colizeum

## Как вносить правки, когда сайт уже работает

**Да, править функционал можно в любой момент.** Сайт на домене — это не
«залитая и застывшая» версия, а обычный запущенный проект. Порядок такой:

1. Правки делаются на компьютере (вами или мной) и уезжают в GitHub.
2. На сервере выполняется одна команда — и сайт обновляется.

На сервере:

```bash
cd /var/www/colizeum
./scripts/deploy.sh
```

Скрипт сам сделает резервную копию, заберёт свежий код, обновит схему базы,
пересоберёт и перезапустит. Сайт будет недоступен несколько секунд на моменте
перезапуска.

Первый раз нужно разрешить запуск скриптов:

```bash
chmod +x scripts/*.sh
```

**Данные при обновлении не теряются.** База и загруженные файлы лежат отдельно
от кода, обновление их не трогает. Сид (который стирает базу) в скрипт не
входит специально.

### Как безопасно проверять крупные переделки

Мелкие правки можно катить сразу. Для крупных — сначала посмотрите их на своём
компьютере (`npm run dev`), убедитесь, что всё как надо, и только потом
обновляйте сервер.

## Бэкапы — обязательно

Код лежит в GitHub и восстановится всегда. А **база и загруженные документы
существуют только на сервере**. Если сервер умрёт, восстановить их будет
неоткуда. Настройте ежедневную копию:

```bash
chmod +x /var/www/colizeum/scripts/backup.sh
crontab -e
```

Выберите редактор (`1` — nano) и добавьте строку в конец файла:

```
0 3 * * * cd /var/www/colizeum && ./scripts/backup.sh >> /var/log/colizeum-backup.log 2>&1
```

Копии будут складываться каждую ночь в 3:00 в `/var/www/colizeum-backups` и
храниться две недели.

Раз в месяц скачивайте копию к себе — на случай, если пропадёт сам сервер.
На своём компьютере, в PowerShell:

```powershell
scp root@123.45.67.89:/var/www/colizeum-backups/* C:\Users\Artur\Downloads\backups\
```

## Перенести данные, которые уже наработаны локально

Если на рабочем компьютере уже есть реальные клиенты и документы, их можно
перенести на сервер вместо демо-данных.

На своём компьютере, из папки проекта:

```powershell
scp prisma\dev.db root@123.45.67.89:/var/www/colizeum/prisma/dev.db
scp -r storage root@123.45.67.89:/var/www/colizeum/
```

Затем на сервере:

```bash
cd /var/www/colizeum
npx prisma db push
pm2 restart colizeum
```

> ⚠️ Это **заменит** базу на сервере. Делайте до того, как сотрудники начнут
> работать на домене, иначе их работа сотрётся.

## Если что-то сломалось

| Что видите | Что делать |
| --- | --- |
| Сайт не открывается | `pm2 status` — сервис должен быть `online` |
| Ошибка на странице | `pm2 logs colizeum --lines 50` — покажет причину |
| «502 Bad Gateway» | Сервис упал: `pm2 restart colizeum` |
| Не грузятся файлы | Проверьте `client_max_body_size 50m` в конфиге nginx |
| Сообщения приходят с задержкой | Проверьте блок `/api/chat/stream` в конфиге nginx |
| ИИ не отвечает | `npm run ai:check` — покажет, что именно не так |
| Кончилось место | `df -h`, затем чистка: `rm -rf .next && npm run build` |

Перезапустить всё целиком:

```bash
pm2 restart colizeum
systemctl reload nginx
```

## Что стоит сделать позже

Сейчас сервис рассчитан на один сервер — этого хватает для отдела. Когда
понадобится расти, потребуются: перенос базы на PostgreSQL, файлы в S3-хранилище
и запуск нескольких копий приложения. Пока в этом нет нужды: SQLite на одном
сервере спокойно держит нагрузку небольшой команды.

Ещё стоит закрыть сервер базовым фаерволом:

```bash
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
```
