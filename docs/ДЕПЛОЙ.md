# Запуск сервиса на домене

Пошаговая инструкция: от пустого кабинета хостинга до работающего сайта на
вашем домене. Рассчитана на человека без опыта администрирования — команды
копируются по одной, каждая объяснена.

Времени: около часа вместе с ожиданием домена.

---

## Какой хостинг выбрать

Нужен **обычный VPS** — виртуальный сервер с постоянным диском. Не подойдут
Vercel и подобные «облака без сервера»: сервис хранит базу в файле рядом с
собой, документы — на диске, а мгновенный чат держит подключения в памяти
процесса. Там всё это будет пропадать при каждом запросе.

Три подходящих российских провайдера. Устроены одинаково: Ubuntu, доступ по
паролю root на почту, домены в том же кабинете. **Инструкция ниже работает с
любым из них** — различаются только первые два шага.

| | Beget | Timeweb Cloud | Reg.ru |
| --- | --- | --- | --- |
| 2 ядра / 4 ГБ | от ~600–900 ₽/мес | ~1500 ₽/мес | ~1000–1400 ₽/мес |
| Домен в том же кабинете | да | да | да, крупнейший регистратор |
| Автоматические копии сервера | **бесплатно, 14 дней** | платно | платно |
| Панель | самая простая | простая | простая |

**Рекомендация — Beget**, и вот почему именно для этого проекта.

База и все загруженные документы существуют **только на сервере**. Код
восстановится из GitHub всегда, данные — неоткуда. У Beget автоматическое
резервное копирование включено в тариф бесплатно, то есть вы получаете второй,
независимый уровень защиты данных даром — ровно там, где у проекта самое
слабое место. Свои ночные копии (см. раздел «Бэкапы») всё равно настраиваем,
но два независимых механизма лучше одного.

Timeweb Cloud — честная альтернатива, если важнее масштаб провайдера
(SLA 99,98 %, дата-центры Tier III), но за копии придётся доплачивать.

> Яндекс Облако для такой задачи не годится: домены там не продаются, вход
> только по SSH-ключам, трафик закрыт группами безопасности, и стоит это вдвое
> дороже при том же результате.

## Шаг 1. Купить сервер

В кабинете выбранного провайдера закажите VPS с такими параметрами:

| Параметр | Значение |
| --- | --- |
| Процессор | 2 ядра |
| Память | 4 ГБ |
| Диск | 40 ГБ SSD/NVMe |
| Система | **Ubuntu 24.04** |

На почту придут **IP-адрес** сервера и **пароль root**. Запишите их.

> Если провайдер предлагает панель управления (ISPmanager, cPanel) — она не
> нужна, только удорожает тариф. Всё делается командами из инструкции.

---

## Шаг 2. Купить домен

Берите там же, где сервер — будет один кабинет вместо двух. Домен `.ru` стоит
около 200–400 ₽ в год.

**Регистрируйте на себя и на личную почту**, не на корпоративную. Корпоративную
при уходе из компании отключают, и вместе с ней теряется доступ к домену.
Подробнее — `docs/ПРАВА_НА_РАЗРАБОТКУ.md`.

Затем в настройках DNS домена добавьте две записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | IP-адрес сервера |
| A | `www` | IP-адрес сервера |

Изменения расходятся от 10 минут до нескольких часов. Пока ждёте — делайте
следующие шаги, они от домена не зависят. Проверить у себя:

```powershell
nslookup ваш-домен.ru
```

Если в ответе виден IP вашего сервера — готово.

---

## Шаг 3. Подключиться к серверу

На своём компьютере откройте PowerShell:

```powershell
ssh root@123.45.67.89
```

Подставьте свой IP. На вопрос про «continue connecting» ответьте `yes`. Затем
введите пароль из письма — **при вводе он не отображается**, это нормально:
печатайте вслепую и жмите Enter.

Дальше все команды выполняются на сервере, в этом же окне.

Сразу смените пароль root на свой:

```bash
passwd
```

## Шаг 4. Установить программы

Одной командой — Node.js 22, git, веб-сервер nginx, менеджер процессов pm2 и
утилита для бесплатного HTTPS.

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs git nginx certbot python3-certbot-nginx sqlite3
npm install -g pm2
```

Проверка: `node --version` должно ответить `v22.` с чем-то.

## Шаг 5. Скачать проект

Репозиторий закрытый, нужен ключ доступа — **Personal Access Token**:

1. github.com → аватар справа сверху → **Settings**
2. В самом низу слева → **Developer settings**
3. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
4. Название любое, срок «No expiration», галочка **repo**
5. **Generate token** и сразу скопируйте строку `ghp_…` — второй раз её не покажут

На сервере:

```bash
mkdir -p /var/www && cd /var/www
git clone https://github.com/ArturFirstow/Colizeum__CRM.git colizeum
cd colizeum
git checkout claude/service-blueprint-frontend-ref797
git config --global credential.helper store
```

Спросит логин — введите `ArturFirstow`. Спросит пароль — **вставьте токен**
`ghp_…`, а не пароль от GitHub. Последняя строка нужна, чтобы токен не
спрашивали при каждом обновлении.

## Шаг 6. Настроить переменные

```bash
cp .env.example .env
openssl rand -base64 32
```

Вторая команда выдаст случайную строку — скопируйте её. Это секрет для подписи
входа: если его не поменять, чужой человек сможет подделать вход в сервис.

```bash
nano .env
```

Приведите файл к такому виду:

```
DATABASE_URL="file:./dev.db"
AUTH_SECRET="строка-из-openssl"

STORAGE_DRIVER="local"
STORAGE_LOCAL_DIR="./storage"

AI_PROVIDER="deepseek"
AI_API_KEY="ваш-ключ-от-deepseek"

SEED_PW_FIRSTOV="пароль-артура"
SEED_PW_IVANUSHKIN="пароль-руководителя"
SEED_PW_YANYUK="пароль-марины"
SEED_PW_TURINOVA="пароль-екатерины"
SEED_PW_CHEPELYUK="пароль-артема"
```

Сохранить и выйти: `Ctrl+O`, `Enter`, `Ctrl+X`.

> **Пароли сотрудников обязательны.** На боевом сервере сид откажется работать
> без них: запасные пароли лежат в открытом коде репозитория и известны всем,
> у кого есть к нему доступ. Задайте по 8+ символов и раздайте сотрудникам
> лично — при первом входе каждый сменит свой сам кнопкой в боковом меню.

## Шаг 7. Первый запуск

```bash
npm ci
npx prisma generate
npx prisma db push
NODE_ENV=production npx prisma db seed
```

> ⚠️ **Сид выполняется ровно один раз.** Он стирает базу и создаёт её заново.
> Когда сервис уже работает с реальными данными, его запуск сотрёт всю работу
> отдела. Для обновлений есть `npx prisma db push` — она добавляет новые поля
> и **сохраняет** данные.
>
> Страховка встроена: без заданных `SEED_PW_*` сид останавливается **до**
> очистки базы и ничего не трогает.

Собираем и запускаем:

```bash
npm run build
pm2 start npm --name colizeum -- start
pm2 save
pm2 startup
```

Последняя команда напечатает ещё одну — скопируйте её и выполните. Это нужно,
чтобы сервис поднимался сам после перезагрузки сервера.

Проверка: `curl -I http://127.0.0.1:3000` должно ответить `HTTP/1.1 200 OK`.

## Шаг 8. Открыть сайт наружу

nginx принимает запросы из интернета и передаёт их сервису.

```bash
nano /etc/nginx/sites-available/colizeum
```

Вставьте, заменив `ваш-домен.ru` на свой:

```nginx
server {
    listen 80;
    server_name ваш-домен.ru www.ваш-домен.ru;

    # Документы и презентации бывают тяжёлыми.
    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Мессенджер держит постоянное соединение ради мгновенных сообщений.
    # Без этих строк nginx его буферизует и рвёт по таймауту.
    location /api/chat/stream {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 24h;
    }
}
```

```bash
ln -sf /etc/nginx/sites-available/colizeum /etc/nginx/sites-enabled/colizeum
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

`nginx -t` должен ответить `syntax is ok` и `test is successful`.
Откройте `http://ваш-домен.ru` — появится страница входа.

## Шаг 9. Включить HTTPS

```bash
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

Спросит почту (для писем об истечении сертификата) и согласие с условиями. На
вопрос про перенаправление выберите **2** — весь трафик на HTTPS.

Сертификат бесплатный и продлевается сам. Проверить автопродление:
`systemctl status certbot.timer`.

Теперь сайт открывается по `https://ваш-домен.ru` с замочком.

Снаружи останутся доступны только вход по SSH и сам сайт.

## Как вносить правки, когда сайт уже работает

**Править функционал можно в любой момент.** Сайт на домене — не «застывшая»
версия, а обычный запущенный проект.

Правки уезжают в GitHub, а на сервере выполняется одна команда:

```bash
cd /var/www/colizeum
./scripts/deploy.sh
```

Скрипт сам делает резервную копию, забирает свежий код, обновляет схему базы,
пересобирает и перезапускает. Сайт полежит несколько секунд на перезапуске.

Самый первый раз разрешите запуск скриптов:

```bash
chmod +x scripts/*.sh
```

**Данные при обновлении не теряются** — база и загруженные документы лежат
отдельно от кода. Сид, который стирает базу, в скрипт намеренно не входит.

Мелкие правки можно катить сразу. Крупные переделки сначала посмотрите у себя
(`npm run dev`), убедитесь, что всё как надо, и только потом обновляйте сервер.

## Бэкапы — три уровня

Код лежит в GitHub и восстановится всегда. **База и загруженные документы
существуют только на сервере** — если он пропадёт, взять их будет неоткуда.

### Уровень 1. Копии провайдера

У Beget автоматическое копирование включено и бесплатно (14 дней). У Timeweb и
Reg.ru — включается отдельной платной услугой в панели. Включите: это защищает
от поломки самой машины.

### Уровень 2. Наши копии, каждую ночь

```bash
chmod +x /var/www/colizeum/scripts/backup.sh
crontab -e
```

Выберите редактор (`1` — nano) и добавьте строку в конец файла:

```
0 3 * * * cd /var/www/colizeum && ./scripts/backup.sh >> /var/log/colizeum-backup.log 2>&1
```

Каждую ночь в 3:00 создаётся копия базы и загруженных документов, хранится две
недели.

### Уровень 3. Копия вне сервера

Раз в месяц скачивайте к себе — на случай, если пропадёт сам сервер:

```powershell
scp root@123.45.67.89:/var/www/colizeum-backups/* C:\Users\Artur\Downloads\backups\
```

## Перенести наработанные данные

Если на рабочем компьютере уже есть реальные клиенты и документы, их можно
перенести вместо демо-данных.

```powershell
scp prisma\dev.db root@123.45.67.89:/var/www/colizeum/prisma/dev.db
scp -r storage root@123.45.67.89:/var/www/colizeum/
```

Затем на сервере:

```bash
cd /var/www/colizeum
npx prisma db push
pm2 restart colizeum
```

> ⚠️ Это **заменит** базу на сервере. Делайте до того, как сотрудники начнут
> работать на домене, иначе их работа сотрётся.

## Если что-то сломалось

| Что видите | Что делать |
| --- | --- |
| Сайт не открывается | `pm2 status` — сервис должен быть `online` |
| Ошибка на странице | `pm2 logs colizeum --lines 50` — покажет причину |
| «502 Bad Gateway» | Сервис упал: `pm2 restart colizeum` |
| Не грузятся файлы | Проверьте `client_max_body_size 50m` в конфиге nginx |
| Сообщения приходят с задержкой | Проверьте блок `/api/chat/stream` в конфиге nginx |
| ИИ не отвечает | `npm run ai:check` — покажет, что именно не так |
| Сид ругается на пароли | Так и задумано: задайте `SEED_PW_*` в `.env` |
| Кончилось место | `df -h`, затем `rm -rf .next && npm run build` |

Перезапустить всё целиком:

```bash
pm2 restart colizeum
systemctl reload nginx
```

## Что стоит сделать позже

Сейчас сервис рассчитан на один сервер — этого достаточно для отдела. Когда
понадобится расти: перенос базы на PostgreSQL, файлы в объектное хранилище
(в коде уже предусмотрено переключение `STORAGE_DRIVER`) и запуск нескольких
копий приложения.

Ещё стоит запускать сервис от отдельного пользователя, а не от root — сейчас,
ради простоты инструкции, всё работает от администратора. Для машины, на
которой не крутится ничего другого, это приемлемо, но не идеально.
