# Дневник → таблица отчётности

Заполнили карточку встречи в «Дневнике» — строка сама появилась в вашей
Google-таблице. Ниже — как это включить. Занимает 10 минут, делается один раз.

## Как это работает

```
Дневник (карточка встречи) → сервис → скрипт внутри вашей таблицы → новая строка
```

Google не разрешает посторонним программам писать в таблицу «просто так» — нужен
доступ изнутри самой таблицы. Поэтому мы кладём в неё маленький скрипт-приёмник.
Ключей Google, облачной консоли и сервисных аккаунтов не требуется.

**Важное свойство:** скрипт раскладывает данные по колонкам **по их названиям в
шапке листа**. Колонки можно переставлять, переименовывать и добавлять новые —
код при этом менять не нужно.

---

## Шаг 1. Кладём скрипт в таблицу

1. Откройте свою таблицу отчётности.
2. Меню **Расширения** → **Apps Script**. Откроется новая вкладка с редактором.
3. Удалите весь текст, который там был.
4. Скопируйте содержимое файла `deploy/google-apps-script.gs` из проекта и вставьте.
5. В самом верху замените строку:

```js
var TOKEN = "ПОМЕНЯЙТЕ_НА_СВОЮ_ДЛИННУЮ_СТРОКУ";
```

на любой свой длинный набор символов, например `colizeum-7f3k9x2mQp`. Запомните
его — он понадобится на шаге 3.

6. Если строк учёта несколько листов и нужен конкретный — впишите его имя:

```js
var DEFAULT_SHEET = "Учёт встреч";
```

Оставите пустым — скрипт будет писать в первый лист таблицы.

7. Нажмите значок дискеты (**Сохранить проект**).

## Шаг 2. Публикуем скрипт

1. Кнопка **Начать развёртывание** (Deploy) → **Новое развёртывание**.
2. Шестерёнка рядом с «Выберите тип» → **Веб-приложение**.
3. Заполните:
   - **Описание** — любое, например «Приём встреч из CRM»;
   - **Запуск от имени** — **Я** (ваш аккаунт);
   - **У кого есть доступ** — **Все**.

   > «Все» здесь означает «любой, кто знает адрес». Именно поэтому у нас есть
   > токен из шага 1: без него скрипт ничего не запишет.

4. **Развернуть**. Google попросит разрешения — **Разрешить доступ**, выберите
   свой аккаунт, на экране «Google не подтвердил приложение» нажмите
   **Дополнительные настройки** → **Перейти к проекту**. Это ваш собственный
   скрипт, предупреждение штатное.
5. Скопируйте **URL веб-приложения** — длинный адрес вида
   `https://script.google.com/macros/s/AKfy…/exec`.

**Проверка:** откройте этот адрес в браузере. Должно появиться
`{"ok":true,"service":"colizeum-meetings"}`.

## Шаг 3. Прописываем адрес в сервисе

На сервере откройте настройки:

```bash
nano /var/www/colizeum/.env
```

Добавьте в конец три строки (адрес и токен — свои):

```
MEETINGS_SHEET_WEBHOOK_URL="https://script.google.com/macros/s/AKfy…/exec"
MEETINGS_SHEET_TOKEN="colizeum-7f3k9x2mQp"
MEETINGS_SHEET_TAB=""
```

`MEETINGS_SHEET_TAB` — имя листа, если хотите переопределить его из сервиса;
пусто — используется лист из скрипта.

Сохранить: Ctrl + O → Enter → Ctrl + X. Перезапустить:

```bash
pm2 restart colizeum
```

На своём компьютере (для локальной работы) то же самое добавьте в файл `.env` в
папке проекта и перезапустите `npm run dev`.

## Шаг 4. Проверяем

1. Откройте «Дневник», тип записи — **Транскрипт**.
2. Вставьте расшифровку встречи, нажмите **«Разобрать транскрипт»** — ИИ заполнит
   дату, время начала и окончания, участников и ссылки.
3. Проверьте поля глазами, при необходимости поправьте. Продолжительность
   считается сама с шагом 0,5 часа.
4. **Добавить**. Под формой появится «Запись сохранена и строка ушла в таблицу
   отчётности», а в таблице — новая строка.

## Какие данные уходят в таблицу

Скрипт ищет в шапке листа колонки с такими названиями (регистр, пробелы и знаки
препинания не важны, синонимы из списка тоже подходят):

| Что отправляем | Как может называться колонка |
|---|---|
| Дата встречи | «Дата встречи», «Дата», «День встречи» |
| Время начала | «Время начала», «Начало», «Начало встречи» |
| Время окончания | «Время окончания», «Окончание», «Конец» |
| Продолжительность | «Продолжительность», «Длительность», «Часы», «Количество часов» |
| Участники | «Участники», «Участники встречи», «Участник встречи» |
| С кем встреча | «С кем встреча» |
| Клиент | «Клиент», «Контрагент», «Компания» |
| Сотрудник | «Сотрудник», «Менеджер», «Ответственный» |
| Ссылка на протокол | «Ссылка на протокол», «Протокол» |
| Ссылка на встречу | «Ссылка на встречу», «Ссылка на запись», «Запись» |
| Комментарий | «Комментарий», «Примечание», «Итоги» |

Колонок, которых нет в вашей шапке, сервис просто не заполняет. Если какая-то
колонка называется иначе и не подхватилась — допишите её название в словарь
`ALIASES` в начале скрипта и сохраните проект заново.

Продолжительность уходит в формате `0,5` / `1,0` / `1,5` — с запятой, как принято
в таблицах учёта.

## Если что-то не так

| Что видно | Что делать |
|---|---|
| «Выгрузка в таблицу пока не настроена» | Не заданы переменные из шага 3 или сервис не перезапущен |
| «Таблица ответила: Неверный токен» | Токен в `.env` и в скрипте различаются |
| «Таблица ответила 401/403» | В развёртывании не выбрано «У кого есть доступ: Все» |
| «Лист не найден» | Имя листа в `MEETINGS_SHEET_TAB` или `DEFAULT_SHEET` написано с опечаткой |
| Строка появилась, но колонки пустые | Названия колонок не совпали — добавьте их в `ALIASES` |

Пока выгрузка не настроена, ничего не теряется: в ленте дневника у каждой встречи
есть кнопка **«Отправить в таблицу»**, которая копирует готовую строку в буфер
обмена — её можно вставить в таблицу вручную.

> После изменения кода скрипта развёртывание нужно обновить: **Начать
> развёртывание** → **Управление развёртываниями** → карандаш → «Версия: Новая» →
> **Развернуть**. Адрес при этом не меняется.
