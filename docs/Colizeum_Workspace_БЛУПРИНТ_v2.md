> Источник: Google Doc «Colizeum Workspace — Технический блупринт v2». Это полное
> техническое задание и архитектурный чертёж внутреннего сервиса менеджера
> рекламных проектов сети киберклубов COLIZEUM. Значками помечены: ⚠️ — точка на
> выверку; 🔒 — требование безопасности/приватности; 🤖 — AI-функция; 🏛 —

## 1. Продукт

Приватный веб-сервис для одного отдела (рекламные проекты COLIZEUM), объединяющий CRM, хранилище документов с версионированием, базу знаний и рабочий дневной журнал. Пользователи: ведущий менеджер (Owner) и младший менеджер/помощник (Manager), каждый с нескольких устройств → общий «дом»: общая БД + файловое хранилище, доступ по логину из браузера.

**Боль, которую снимаем:** «что-то упустил» (статусы в голове и чатах); потерянные версии документов; ручная сборка КП/спецификаций/ОРД-ТЗ/отчётов; неформализованная специфика.

**Принцип автоматизации:** сервис — ассистент, снимающий рутину, а не самоуправляемый конвейер. AI-функции включаются по запросу и всегда предлагают результат к подтверждению.

## 4. Архитектура

Монолитное full-stack-приложение в одном репозитории: UI → API-роуты → сервисы → репозитории → БД + объектное хранилище. AI-вызовы — отдельный сервисный слой.

**Стек:** TypeScript; Next.js (App Router); React + Tailwind (чёрный + жёлтый, мотив «ХО»); Prisma + SQLite (dev) → PostgreSQL (prod); файлы — локальный диск (dev) → S3-совместимое хранилище (prod) за интерфейсом `StorageProvider`; Auth.js/credentials (bcrypt, httpOnly cookie); Anthropic SDK (только сервер); Zod на границах API; фоновые задачи (v2).

**Ключевые принципы:** файлы — в объектном хранилище, метаданные — в БД; идемпотентность загрузок по SHA-256; инварианты — в сервисном слое; AI никогда не пишет в БД напрямую (предложение → подтверждение); всё логируется (аудит-лог v2).

## 5. Модель данных

Сущности: User, Advertiser, Contact, Deal, Document, DocumentVersion, Task, MediaPlan, MediaPlanLine, Invoice, Payment, ClosingDoc, OrdMarking, PromoBatch, KnowledgeArticle, Person, JournalEntry, AuditLog (v2), Job (v2). Полный список полей — в `prisma/schema.prisma`.

**Document.type:** Договор, Приложение, Спецификация, Заказ, ДС, КП, Медиаплан, Счёт, Платёжное поручение, УПД, Отчёт об оказанных услугах, Акт сверки, Правила акции, Креатив, NDA/Согласие, Прочее.

## 6. Модули (вкладки)

1. **Дашборд «Сегодня»** — «◆ Решения, которые ждут вас», задачи, зависшие сделки, блокеры, свежий журнал.
2. **Рекламодатели (CRM)** — карточки, контакты, сделки, документы. Карточка при первом касании; подрядчиков не заводим.
3. **Сделки / трекер стадий** — список + канбан, инварианты стадий.
4. **Документы** (ядро MVP) — дерево «рекламодатель → тип → документ → версии», загрузка/версии/скачивание. Раскладка ручная в MVP.
5. **Задачи** — по видам, делегирование, статусы, дедлайны.
6. **Медиапланы и КП-калькулятор** (генерация — v2).
7. **ОРД / маркировка** — реестр ЕРИД, ежемесячное закрытие актов.
8. **Промокоды** — партии по механикам, налоги, отсрочка ≥12 ч.
9. **Финансы / закрывающие** — Счёт → ПП → УПД → Отчёт → Акт сверки; контроль р/с; НДС по дате.
10. **База знаний** — статьи по категориям, полнотекстовый поиск, таблицы.
11. **Дневной журнал** — EOD/транскрипты; AI-разбор — v2, MVP — ручная запись.

## 7. Бизнес-логика, стадии, инварианты

### 7.1 Канон стадий (11 нормализованных)

1. Лид / квалификация · 2. МП и КП · 3. Согласование договора · 4. Согласование приложений / ЭДО · 5. Договор / подписание · 6. Документооборот / подготовка · 7. Оплата / предоплата · 8. Интеграция / тех. подключение · 9. Размещение / оказание услуг · 10. Маркировка и отчётность · 11. Закрывающие.

«Рабочие 9» — укрупнённое представление в канбане.

### 7.2 Маршрут согласования договора

Юрист (Екатерина) → Главбух (Ольга) → если сумма > 3 млн ИЛИ нестандартный → СЕО (через Сашу). До 3 млн и классический — клиенту сразу.

### 7.3 Инварианты (на бэкенде)

- **Последовательные приложения (Т-Банк):** нельзя пометить Приложение №N+1 «на согласовании», пока №N не подписано.
- **Правки после подписания → ДС** (кейс Алабуга).
- **Финмаршрутизация:** платежи по клубу на ИП нельзя через счёт УК; смена ИП сдвигает интеграцию эквайринга.
- **Предоплата как условие старта:** размещение (стадия 9) не открывается без предоплаты (МТС 40 %; Алабуга — за первый месяц; типовое 100 %).
- **НДС по дате:** 2025 → 20 %, 2026 → 22 %.

## 8. AI-функции (🤖, v2)

Только с сервера; строгий JSON-ответ; экран подтверждения перед записью в БД; контекст из базы знаний. Функции: автораспределение загрузок; разбор входящего документа; генерация КП; генерация ОРД-ТЗ; черновик отчёта об услугах; разбор EOD-сводки/транскрипта.

## 9. Контракт API (REST)

Аутентификация — cookie-сессия. Ответы JSON, валидация Zod, единый формат ошибки `{ error: { code, message } }`. Роуты по advertisers / deals / documents+versions / tasks / mediaplans / invoices+payments / closing-docs / ord / promo / knowledge / journal / ai/*.

## 10. Файловое хранилище и версионирование

Ключ объекта: `advertisers/{advertiserId}/documents/{documentId}/v{versionNo}/{sanitizedFileName}`. В БД — только метаданные. Новая загрузка → инкремент `versionNo`, `currentVersionId` перещёлкивается, старые версии остаются. Дедуп по sha256. Скачивание через backend с проверкой прав. Абстракция `StorageProvider` (local/S3).

## 11. Безопасность, приватность, бэкап

🔒 Приватный доступ (2 аккаунта, регистрация закрыта); bcrypt + httpOnly/secure cookie + CSRF; секреты только в env; персональные данные не в URL; HTTPS в прод; ежедневный бэкап БД + версионирование бакета; аудит-лог (v2).

## 12. План сборки по фазам

- **Фаза 0 — Каркас:** репозиторий, стек, Prisma-схема (все сущности), auth на 2 аккаунта, пустые вкладки, фирменный стиль. DoD: поднимается локально, вход работает, схема создана.
- **Фаза MVP — Документы + Рекламодатели:** карточки, дерево документов, версионирование, скачивание, ручная раскладка. DoD: завести рекламодателя, загрузить договор и новую версию, увидеть историю, скачать любую версию.
- **Фаза v1 — Рабочий инструмент:** трекер 11 стадий + канбан + инварианты; задачи; дашборд; медиапланы; финансовая цепочка; ОРД; промокоды; база знаний с поиском; журнал.
- **Фаза v2 — Умный ассистент (🤖):** AI-функции; RBAC + аудит-лог; фоновые задачи.
- **Фаза v3 — Прод:** PostgreSQL + S3 + HTTPS; бэкапы; доступ с любого устройства.

## 13. Развёртывание

Локально: `npm install` → `.env` → `prisma migrate/db push` → `npm run dev`. Прод: управляемый PostgreSQL + S3-бакет + деплой на Railway/Render/VPS, секреты в панели хостинга.

## 14. Нефункциональные требования
