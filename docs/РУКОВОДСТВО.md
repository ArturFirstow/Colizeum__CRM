# Colizeum Agency — рабочий сервис отдела

Сценарий для видеоурока сотрудникам и презентации руководству.
Адрес: **colizeum-agensy.space**

---

# Часть 1. Что это и зачем

Раньше работа отдела жила в десятке мест: договоры в почте, сроки в голове, суммы в таблицах, задачи в переписке. Когда менеджер уходит в отпуск, вместе с ним уходит и половина знания о клиенте.

Сервис собирает это в одно место. Один клиент — одна карточка, в ней договор, деньги, сроки, документы, история переписки и всё, что по нему решали.

**Три вещи, которых нет в готовых CRM:**

- **ОРД и маркировка рекламы** — требование закона, за нарушение штрафы. Здесь ЕРИД, креативы и акты живут прямо в сделке.
- **Промокоды и взаиморасчёты** по ним — наша специфика.
- **Разбор транскрипта встречи** — вставили расшифровку, сервис сам достал дату, время, участников и заполнил строку в таблице учёта.

# Часть 2. Где хранятся данные и что с безопасностью

*Этот блок — для учредителей. Отвечает на вопрос «а не утечёт ли?»*

## Где физически лежат данные

**Свой сервер, арендованный у российского хостинга.** Не чужое облако, не иностранный сервис, не подписка на стороннюю CRM. Сервер — как отдельный компьютер, доступ к нему есть только у администратора сервиса.

На этом сервере лежит всё:

| Что | Где |
|---|---|
| База данных: клиенты, сделки, суммы, задачи | один файл на диске сервера |
| Загруженные файлы: договоры, счета, макеты | папка на диске того же сервера |
| Резервные копии | там же, отдельная папка |

Никакой сторонней компании доступа к этим данным нет.

## Кто и как попадает внутрь

- Вход **только по логину и паролю**. Регистрация закрыта — сотрудника заводит администратор вручную.
- **Пароли не хранятся.** В базе лежит их необратимый математический отпечаток. Даже человек с полным доступом к базе прочитать пароль не сможет — только назначить новый.
- Соединение всегда **зашифровано (HTTPS)**, сертификат обновляется автоматически. Между браузером сотрудника и сервером никто не прочитает переписку.
- На сервере закрыт весь доступ снаружи, **кроме самого сайта**. Сама программа наружу не смотрит.

## Кто что видит внутри

Это не декорация — ограничение работает на уровне запросов к базе, а не «спрятали кнопку».

| Роль | Видит |
|---|---|
| **Менеджер** | только своих клиентов, свои сделки, свои документы и деньги |
| **Руководитель** | весь отдел: сводки, воронку, бюджет |
| **Турнирный менеджер** | только турнирный контур; рекламные разделы ему просто не показываются |
| **Администратор** | всё + управление доступами |

Менеджер физически не может открыть карточку чужого клиента, даже зная адрес страницы.

## Резервные копии

Каждую ночь автоматически создаётся копия базы и всех загруженных файлов. Хранятся последние 14 копий — то есть откатиться можно на две недели назад.

## Что уходит наружу — честный список

Сервис обращается к внешним сервисам ровно в четырёх случаях:

1. **ИИ-напарник** — текст запроса уходит провайдеру (DeepSeek). Уходит только то, что нужно для ответа, и только когда сотрудник сам нажал кнопку.
2. **Уведомления в Telegram** — текст уведомления («по такому-то клиенту поднят блокер»).
3. **Таблица отчётности по встречам** — строка с показателями встречи уходит в вашу же Google-таблицу.
4. **Заявки с сайта** — читаются из вашей же Google-таблицы формы.

Всё остальное — договоры, суммы, реквизиты, документы — **не покидает сервер**.

## Что стоит улучшить дальше — говорим прямо

Скрывать слабые места смысла нет, их всё равно спросят:

- **Резервные копии лежат на том же сервере.** Если сервер погибнет целиком — погибнут и копии. Правильный следующий шаг: выгружать копию во внешнее хранилище.
- **Нет журнала действий.** Не видно, кто и когда изменил сумму в сделке. Для команды из пяти человек не критично, при росте — понадобится.
- **Данные шифруются при передаче, но не на диске.** Защита здесь — ограничение доступа к самому серверу.

Всё три пункта решаемы, вопрос приоритета.

# Часть 3. Путь клиента — сквозной сценарий

Это основной маршрут. Если понять его, остальное складывается само.

**1. Заявка** приходит с сайта в раздел «Входящие с сайта».

**2. Клиент.** Заводим карточку в «Клиентах»: название, юрлицо, ИНН, реквизиты, контакты.

**3. Сделка.** Внутри клиента создаём сделку — конкретный проект с конкретным бюджетом. Сделка идёт по стадиям: Лид → КП → Договор → Подписание → Размещение → Закрытие.

**4. Документы.** В карточке сделки — договор, потом медиаплан, потом счета. Именно в таком порядке: сервис не даст перепрыгнуть через этап, если чего-то не хватает.

**5. Деньги.** Счёт → платёжное поручение → УПД. Плановые платежи раскладываются по месяцам в календаре.

**6. Размещение** стартует после предоплаты и попадает в календарь размещений.

**7. ОРД.** Получаем ЕРИД, прикладываем креатив и акт.

**8. Закрытие.** Закрывающие документы, акт сверки.

# Часть 4. Разделы — что за что отвечает

## Ежедневное

**Сегодня** — стартовая страница. Цифры по вашим клиентам, что ждёт решения, поручения руководителя, задачи и блокеры, статус дня.

**Задачи** — доска. Задачи от руководителя помечены значком «Поручение». Клик по карточке открывает правку.

**Сделки** — воронка. Карточка сделки — главный экран работы: стадия, сумма, договор, медиаплан, счета, ОРД, промокоды, задачи.

**Мессенджер** — рабочий чат: общий канал и личные переписки, можно привязать сообщение к клиенту или сделке. Рядом с пунктом меню горит счётчик непрочитанного.

**Напарник ИИ** — чат, который знает ваших клиентов. Можно спросить «что у меня по МТС» или бросить файл, и он разложит его по нужным карточкам.

**Дневник** — транскрипты встреч. Вставили расшифровку → кнопка «Разобрать транскрипт» → сервис сам заполнил дату, время, участников и ссылки → при сохранении строка ушла в таблицу отчётности.

## Клиенты и документы

**Клиенты** — карточки контрагентов: реквизиты, контакты, креативы, клиенты агентства.

**Документы** — хранилище с версиями. Новая загрузка не затирает старую: остаётся история.

**База знаний** — как у нас всё устроено: шаблоны, регламенты, договоры, прайсы.

**Входящие с сайта** — заявки с сайта, подтягиваются автоматически. Статус и ответственный ставятся здесь.

**Команда** — сотрудники и доступы. Только у администратора.

## Деньги и размещения

**Оплаты** — календарь платежей по месяцам, счета, платёжки, УПД. Если по клиенту случайно завели лишний платёж, сервис сам подсветит: «разложено больше, чем сумма договоров».

**Календарь размещений** — что и когда выходит, по неделям.

**ОРД / маркировка** — ЕРИД, роли, креативы, акты, срочные позиции.

**Промокоды** — партии кодов, сроки, условия, взаиморасчёты.

# Часть 5. Роль: менеджер

*Кому: Марина, Екатерина*

## Утро — 5 минут

Открываете **«Сегодня»**. Сверху цифры по вашим клиентам, ниже — что требует вас:

- поручения руководителя;
- задачи и блокеры;
- ваши вопросы и ответы на них.

## Работа по клиенту

**Новый клиент:** «Клиенты» → «+ Рекламодатель» → название, юрлицо, ИНН. Реквизиты можно дозаполнить позже кнопкой «Редактировать».

**Новая сделка:** внутри клиента → «+ Сделка». Указываете бюджет и срок. Дальше двигаете по стадиям — сервис проверяет, что для перехода всё готово, и предупреждает, если чего-то нет.

**Документы и файлы:** прямо в карточке сделки. Порядок: договор → медиаплан → счета. Файл, приложенный в сделке, автоматически виден и в «Документах» клиента — дважды загружать не нужно.

## Когда что-то мешает

**Блокер** — когда работа встала: не отвечает клиент, завис договор. Ставите флажок и пишете причину. Сделка подсвечивается у вас и у руководителя, ему приходит уведомление. Разрешилось — снимаете одним кликом.

**«Саша, окни пожалуйста»** — когда нужно решение руководителя: согласовать макет, выдать доступ, подтвердить расход. Кнопка на «Сегодня». Можно приложить файлы прямо в форме. Ответ придёт уведомлением, статус виден в блоке «Мои вопросы».

## После встречи

«Дневник» → тип записи **Транскрипт** → вставляете расшифровку → **«Разобрать транскрипт»**.

Сервис сам заполняет дату, время начала и окончания, участников, ссылки и итоги. Продолжительность считается автоматически с шагом полчаса. Проверяете глазами → «Добавить» → строка уходит в таблицу отчётности.

**Вручную заполнять таблицу больше не нужно.**

## Правила, которые сервис держит за вас

Их не надо помнить — сервис предупредит сам:

- приложения Т-Банка согласуются строго по очереди;
- если после подписания править тело договора нельзя — оформляем допсоглашение;
- платежи по клубу на ИП нельзя проводить через счёт управляющей компании;
- размещение стартует только после предоплаты;
- НДС считается по дате документа: 2025 год — 20 %, 2026 — 22 %.

# Часть 6. Роль: руководитель

*Кому: Александр*

## Обзор отдела

**«Обзор отдела»** отвечает на три вопроса:

1. **Кто чем занят** — сводка по каждому сотруднику: клиенты, сделки, блокеры.
2. **Где встало** — воронка из шести шагов. Клик раскрывает контрагентов с менеджером, суммой и сроком.
3. **Что горит** — блокеры, просроченное, зависшее. Каждый виджет раскрывается в список.

## Решения, которые ждут вас

Сотрудник задаёт вопрос — карточка появляется здесь, а вам приходит уведомление: в Telegram и всплывающим окном на сайте.

Видно, кто спрашивает, по какому клиенту, приложенные файлы. Кнопка **«Решено»** прямо в карточке, можно добавить ответ — он придёт автору.

## Деньги отдела

Экран построен как «одна страница — три вопроса»:

- **Сколько свободно** — карточка месяца: план, факт, полоса освоения.
- **Что ждёт решения** — расходы на согласование, кнопка «Согласовать» прямо в строке.
- **Куда уходит и что приходит** — два списка.

Форма расхода — четыре обязательных поля, бухгалтерия спрятана в «Подробности». Переключатель НДС пересчитывает сумму сам. Выгрузка в CSV.

## Поручения

Кнопка **«Поручить»** в обзоре и в карточке сотрудника. Задача попадает к нему на доску с пометкой «Поручение», плюс уведомление.

## Недельный отчёт

Кнопка **«Недельное ИИ-саммари»** в «Дневнике» — сервис собирает статусы, журнал и сделки за 7 дней и пишет связный текст по каждому партнёру.

# Часть 7. Роль: турнирный менеджер

*Кому: Артём*

Отдельный контур. Рекламные разделы не показываются — только своё.

**Контрагенты** — с кем проводим турниры, воронка статусов от первого контакта до проведения.

**Турниры и сметы** — карточка турнира: формат, даты, статус. Внутри — смета построчно: что закупаем, почём, сколько всего.

**Бронь арены** — помесячный календарь площадки на Шелепихе. Зоны: вся арена, сцена с LED-экраном, сцена с экраном плюс комнаты.

Общие разделы те же, что у всех: «Сегодня», задачи, мессенджер, база знаний, заявки с сайта, напарник ИИ.

# Часть 8. Уведомления

Ничего не теряется, даже если человек не в сервисе.

| Событие | Кто узнает | Как |
|---|---|---|
| Вопрос руководителю | руководитель | Telegram + всплывающее окно на сайте |
| Ответ на вопрос | автор вопроса | Telegram + окно |
| Поручение | сотрудник | Telegram + окно |
| Поднят блокер | руководитель | Telegram + окно |
| Новое сообщение в чате | все участники | счётчик рядом с «Мессенджером» |

Всплывающее окно появляется в правом нижнем углу, клик ведёт в нужный раздел.

# Часть 9. Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Забыли пароль | к администратору — сбрасывает за минуту |
| Не загружается файл | проверьте размер, лимит 60 МБ |
| Не вижу клиента коллеги | так и задумано: каждый видит только своих |
| Данные на экране устарели | обновите страницу сочетанием Ctrl + Shift + R |
| Ошибка на странице | скриншот администратору, чинится по коду |

# Приложение. План видеоурока

Ориентировочно 12–15 минут.

| Блок | Время | Содержание |
|---|---|---|
| 1. Зачем это | 1 мин | Проблема «всё в разных местах» → одно место |
| 2. Вход и «Сегодня» | 2 мин | Показать стартовый экран, объяснить блоки |
| 3. Сквозной путь клиента | 5 мин | Заявка → клиент → сделка → договор → счёт → размещение → ОРД |
| 4. Блокер и вопрос руководителю | 2 мин | Показать на живом примере с уведомлением |
| 5. Дневник и разбор транскрипта | 3 мин | Самый эффектный момент — показать обязательно |
| 6. Где что искать | 1 мин | Пробежка по меню |

**Совет для презентации руководству:** не показывайте всё меню целиком. Покажите один сквозной путь клиента и три вещи, которых нет в готовых решениях — ОРД, промокоды, разбор транскрипта. Остальное упомяните списком.
