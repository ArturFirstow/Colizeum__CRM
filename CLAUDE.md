# Colizeum Agency — проект

Внутренний сервис менеджера рекламных проектов COLIZEUM: **CRM + документы с версионированием + календарь размещений + финансы + ОРД + промокоды + база знаний + журнал**.

Исходное ТЗ — `docs/Colizeum_Workspace_БЛУПРИНТ_v2.md`; поверх него выполнено большое ТЗ на доработку (см. «Текущее состояние»). Читай блупринт при работе над доменной логикой.

## Про пользователя

Пользователь — не программист. Объясняй просто, по-русски. Работай маленькими шагами: один блок → короткое резюме → подтверждение. Не выдумывай доменные данные (реквизиты, цены, документы) — только то, что дал пользователь.

- **Универсальные вложения** (`FileAsset`, `/api/files`, компонент `src/components/ui/FileCell.tsx`): одно хранилище на весь сервис. Ячейки загрузки стоят в карточке сделки (счета, медиапланы, документы), в креативах клиента, в «Документах» и в карточках базы знаний. Поля `advertiserId`/`dealId` заполняются при загрузке — файл из сделки виден и у клиента. Поддержано перетаскивание мышью.
- **Обзор отдела**: воронка укрупнена до 6 шагов (Лид → КП → Договор → Подписание → Размещение → Закрытие), клик раскрывает контрагентов с менеджером, суммой и сроком; виджеты «блокеры / просроченные / зависшие» раскрываются в списки (`DeptFunnel.tsx`).
- **«Сегодня»**: порядок — цифры → «Решения, которые ждут вас» → поручения руководителя → задачи/блокеры → кольца стадий → статус дня.
- **Дневник** — под транскрипты встреч: тип записи, «с кем встреча», клиент, вставка расшифровки и прикрепление файла записи. **Показатели встречи** (дата, начало, окончание, продолжительность шагом 0,5 ч, участники, ссылки на протокол и на встречу, итоги) заполняются кнопкой «Разобрать транскрипт» (`/api/journal/parse-meeting`, ИИ) и при сохранении уходят строкой в Google-таблицу отчётности — `src/lib/services/meeting-sheet.ts` + скрипт-приёмник `deploy/google-apps-script.gs` (колонки сопоставляются ПО НАЗВАНИЯМ в шапке листа, ключи Google не нужны; установка — `docs/MEETINGS_SHEET.md`). Не настроено — кнопка «Отправить в таблицу» копирует готовую строку в буфер.
- **Блокер сделки** — флажок + комментарий (`Deal.blockerActive`): сводки считают блокером только поднятый флажок, снять можно одним кликом (`BlockerToggle`). Свободные тексты сделки очищаются пустым полем (`clearableString` в validation) — раньше пустая строка оставляла сделку «заблокированной» навсегда.
- **Вопрос руководителю** — заметный виджет на «Сегодня» с вложениями прямо в форме (`DecisionRequest.attachmentsKey` → `FileAsset` с `ownerType="decision"`).
- **Прод-деплой** — `deploy/` (setup-server.sh, nginx, pm2, update.sh, backup.sh) + пошаговая инструкция `docs/DEPLOY.md`: Timeweb DNS → AdminVPS → HTTPS.
- **Файлы базы знаний** (`KnowledgeFile`, `/api/knowledge/files`): блок «Файлы и шаблоны» на `/knowledge` — загрузка/скачивание договора, прайса, презентации через StorageProvider (ключи `knowledge/{id}/…`).
- **Поручения руководителя**: Director ставит задачу сотруднику (`Task.assignedById`, `/api/leadership/tasks`, кнопка «Поручить» в обзоре и на карточке сотрудника); у сотрудника — бейдж «🎯 Поручение» на доске задач.

**Заявки с сайта** (`/leads`): поток обращений из формы на colizeum-agency.ru. Тянутся из рабочей Google-таблицы CSV-экспортом (`src/lib/services/leads-sync.ts`, разбор — `src/lib/leads-parse.ts`; ключи Google API не нужны, но таблице нужен доступ «по ссылке — Читатель»). Синк при открытии страницы (не чаще раза в 3 мин) + кнопка «Обновить» (`/api/leads/sync`). Дедуп по `requestid` формы (`Lead.externalId`). Статус/ответственный/заметка живут в CRM и синком не перетираются (`/api/leads/[id]`). Раздел общий для всех сотрудников (без гейтинга по `track`).

**Мессенджер** (`/messenger`): каналы (Channel, «Общий» неудаляемый), сообщения (ChatMessage: закрепление, привязка к клиенту/сделке через денормализ. context), вложения (ChatAttachment через StorageProvider, ключи `chat/{channelId}/{messageId}/…`), поллинг ленты ~4с. Общий для всех сотрудников.
**Команда** (`/team`): админ (Owner) создаёт доступы и правит имя/роль (PATCH `/api/users/[id]`).

**ИИ** (`src/lib/ai.ts` — единый шов). Провайдер выбирается в `.env` строкой `AI_PROVIDER`: `deepseek` и `yandex` — проверено доступны из РФ (у пользователя Qwen и Kimi режет провайдер интернета: ECONNRESET); `qwen`/`kimi` — OpenAI-совместимые; `anthropic` — Claude (из РФ отвечает 403 «Request not allowed»); `openai` — любой другой совместимый сервис. Ключ — `AI_API_KEY`, модель — `AI_MODEL` (по умолчанию qwen-plus / moonshot-v1-32k / claude-sonnet-5), адрес — `AI_BASE_URL` (подставляется по провайдеру). Инструменты напарника — `src/lib/ai-tools.ts`, типы `AiTool`/`AiMessage` нейтральные, поэтому смена провайдера кода не касается. Ошибки провайдера переводятся в человеческий текст (`aiErrorMessage`).

**Передача дел** (`/handover`, `Handover` + `HandoverItem`): сотрудник уходит в отпуск — выбирает своих клиентов, кому передать и до какой даты. Кнопка «Собрать саммари» (`/api/handover/preview`) готовит текст по каждому клиенту: где работа, что подписано и оплачено, что горит, блокеры и сроки — факты собираются из базы (`src/lib/services/handover.ts`), ИИ только пересказывает; без ключа ИИ саммари всё равно формируется списком фактов. Отправка меняет `Advertiser.ownerId` на замещающего и запоминает прежнего владельца в `HandoverItem.previousOwnerId`; «Вернуть дела» ставит всё обратно. Принимающему уходит уведомление.

**Уведомления**: Telegram (`src/lib/services/notify.ts`, настройка — `docs/TELEGRAM.md`) + всплывающие на сайте (`/api/notifications` + `src/components/ui/Notifications.tsx`, опрос раз в 30 с, отдельной таблицы нет — события считаются из сделок/задач/запросов). Маячок непрочитанного в мессенджере — `User.chatSeenAt` + `/api/chat/unread`. Сообщения: личка → Telegram (`notifyChatDm`) + всплывашка; общие каналы → только всплывашка (одной строкой при нескольких), на самой странице мессенджера они подавлены.

**Документация для людей**: `docs/РУКОВОДСТВО.md` — нетехническое описание сервиса по ролям + блок про хранение данных и безопасность (для учредителей).

**Дорожная карта:**
1. ✅ Задачи от руководителя.
2. ✅ ИИ-кнопки в карточках (1A): «Саммари клиента за месяц», «Драфт ДС по шаблону». Нужен `ANTHROPIC_API_KEY`.
3. ✅ Внутренний мессенджер: каналы, **личка (DM)**, вложения, закрепы, привязка к клиенту/сделке, **мгновенный realtime (SSE, `src/lib/chat-events.ts` + `/api/chat/stream`)**.
4. ✅ ИИ-чат ассистент (1B) `/assistant`: чат с инструментами (`aiChat` в `ai.ts` — tool-loop; `/api/ai/chat`). Общий пункт меню.
5. ✅ **Напарник-картотека**: инструменты вынесены в `src/lib/ai-tools.ts` — читающие (list_my_clients, get_client, search_knowledge, list_inbox_files) и **пишущие** (route_file, create_task, add_daily_status, add_journal_entry, ask_leader). В чат можно прикрепить файл: он падает в «Входящие» (`FileAsset.ownerType="inbox"`, `/api/ai/inbox`), напарник определяет клиента/сделку и раскладывает через route_file — файл сразу виден в карточке сделки и в «Документах». Всё в скоупе сотрудника.

⚠️ **Регион:** прямые запросы к Anthropic из РФ отвечают `403 Request not allowed` — ключ рабочий, блокируется адрес. Обход: сервер за рубежом, шлюз через `ANTHROPIC_BASE_URL`, или другой провайдер. Ошибки провайдера переводятся в человеческий текст (`aiErrorMessage` в `ai.ts`).

**ИИ-провайдер:** пока Claude (по решению пользователя — «прикрутить к тебе, позже переключим»). Обвязка провайдер-независимая через `ai.ts`. Открытые вопросы на будущее: (1) важна ли data-residency РФ; (2) какой провайдер вместо Claude.

**НЕ сделано (следующие итерации):** RBAC + аудит-лог, S3, realtime на несколько инстансов (сейчас in-memory, для 1 сервера), турнирные инструменты для ИИ-ассистента (пока видит только рекламный контур). **Ждём от пользователя:** `ANTHROPIC_API_KEY` в `.env` для всех ИИ-функций; база знаний коллеги.

⚠️ **Данные:** `npx prisma db seed` ОЧИЩАЕТ базу (демо-набор заново). После первого запуска на реальных данных использовать только `npx prisma db push` (сохраняет данные, добавляет схему).

**Проверка ИИ:** `npm run ai:scan` — показывает, до каких провайдеров достаёт сеть (ключи не нужны). `npm run ai:check` — делает один тестовый запрос к провайдеру и печатает вердикт (что настроено, куда ушёл запрос, что ответил провайдер). Быстрее, чем гадать через интерфейс.

## Доставка кода

Push из сессии **работает** (с 08.2026, после подключения доступа на запись). Коммитим и пушим в рабочую ветку напрямую. Бандлы (`git bundle` → отправка пользователю) больше не нужны — они были обходом старого read-only доступа.

## Архитектура

- **Монолит**: Next.js 15 (App Router) + TypeScript + Tailwind.
- **БД/ORM**: Prisma + SQLite (dev) → PostgreSQL (prod). Все сущности и связи — `prisma/schema.prisma`. Enum'ы хранятся строками, источник значений — `src/lib/enums.ts`, валидация Zod — `src/lib/validation.ts`.
- **Файлы**: `StorageProvider` (`src/lib/storage/`), dev — локальный диск `./storage`; в БД только метаданные (sha256, версии). Файлы ОРД — ключи `ord/{id}/{kind}/…`.
- **Auth**: cookie-сессия (JWT `jose`, httpOnly), bcrypt, 2 аккаунта. `src/lib/auth.ts`.
- **Слои**: страницы (server components, Prisma напрямую) → клиентские островки (`src/components/**`) → API-роуты (`src/app/api/**`, Zod, `{ error: { code, message } }`) → сервисы (`src/lib/services/**`).
- **Инварианты стадий** — `src/lib/services/deal-stage.ts`: предупреждения → 409 → подтверждение `confirm=true`.

## Незыблемые правила домена

- Приложения Т-Банка согласуются строго по очереди.
- Правки после подписания при запрете правки тела → **ДС** (кейс Алабуга).
- Платежи по клубу на ИП нельзя через счёт УК.
- Размещение стартует только после предоплаты.
- НДС по дате документа: 2025 → 20 %, 2026 → 22 % (`vatRateForDate`).
