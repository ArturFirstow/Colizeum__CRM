# Colizeum Agency — проект

Внутренний сервис менеджера рекламных проектов COLIZEUM: **CRM + документы с версионированием + календарь размещений + финансы + ОРД + промокоды + база знаний + журнал**.

Исходное ТЗ — `docs/Colizeum_Workspace_БЛУПРИНТ_v2.md`; поверх него выполнено большое ТЗ на доработку (см. «Текущее состояние»). Читай блупринт при работе над доменной логикой.

## Правила безопасности при работе над этим проектом

Требование компании 9.1 просит вставлять правила безопасности в начало каждого
разговора с ИИ. Вставлять руками каждый раз никто не будет — поэтому они
записаны здесь, в постоянных инструкциях проекта: так они действуют всегда,
в любой сессии, и их нельзя забыть.

Действуют и для ИИ, и для человека, который правит код:

1. **Реальные персональные данные не попадают в разговор с ИИ.** Ни выгрузки
   из боевой базы, ни скриншоты с ФИО и телефонами, ни дампы. Нужен пример —
   берите вымышленный: «Иван Петров, +7 900 000-00-00».
2. **Секреты не попадают в разговор.** Пароли, токены, ключи API, содержимое
   `.env`. Нужно обсудить настройку — называйте переменную (`AI_API_KEY`), а не
   её значение. Секрет, однажды показанный, считается утёкшим и подлежит смене.
3. **Код от ИИ — черновик.** Перед выкаткой: проверка прав доступа (кто увидит
   эти данные), проверка ввода на сервере, запись в журнал там, где трогаются
   данные людей. Пока ответственный за ИБ не назначен, за это отвечает автор.
4. **Любая новая передача данных наружу записывается** — через `logTransfer`
   (`src/lib/services/transfers.ts`). Новый внешний сервис = новый канал в
   списке `TRANSFER_CHANNELS` с честной пометкой, пересекают ли данные границу.
5. **Сроки и правовые формулировки не выдумывать.** Сроки хранения, основания
   обработки, тексты согласий — решение юриста и ответственного за ПДн. Можно
   предложить черновик, явно подписав его как предложение.
6. **Проверка на боевых данных не делается.** `npx prisma db seed` очищает базу;
   на реальных данных — только `npx prisma db push`.

## Про пользователя

Пользователь — не программист. Объясняй просто, по-русски. Работай маленькими шагами: один блок → короткое резюме → подтверждение. Не выдумывай доменные данные (реквизиты, цены, документы) — только то, что дал пользователь.

Галочками отмечаются рекламные форматы (`AD_FORMATS` в enums — список дал пользователь, не выдумывать); реквизиты клиента, номер договора, суммы и сроки подставляются из карточки. Сохранённые запросы видны в карточке сделки разделом «Отправленные запросы» (текст по клику) и отдельным типом события «Запрос» в хронологии клиента. ⚠️ В тексте стоит подписант со стороны клиента, то есть живой человек, — поэтому `RequestRecord` включён в поиск и удаление по запросу субъекта (`person-data.ts`, удаляется целиком). Три подсказки от домена: у форматов с `needsOrd` в текст добавляется блок про ЕРИД; если у клиента пусты ИНН/адрес/подписант — предупреждение до отправки; если сделка не дошла до предоплаты — предупреждение, что размещать рано. ⚠️ Формулировки — черновик по правилам из базы знаний, образцов от юриста не было; правятся прямо в `request-templates.ts`.
  - **Запрос юристу**: даты периода — календарём; сумма вводится ЧИСТОЙ, с НДС досчитывается сама по ставке из даты договора (`vatRateForDeal` → `withVat`) и уходит в текст тремя строками (с НДС / в т.ч. НДС / без НДС); выпадающие списки — `GEO_OPTIONS` (все клубы РФ / Москва и МО / другое), `CREATIVE_OWNERS` (кто делает макеты), `ERID_OWNERS` (кто получает маркировку — поле включается, только когда выбран интернет-формат), `SIGNING_OPTIONS` (ЭДО / бумага), `PAYMENT_SCHEMES` (100 % предоплата / 50-50 / другое). Поля «к какому сроку нужен документ» нет — убрано по просьбе пользователя.
  - **Два приложения**: галочка «Отдельное приложение под интернет-форматы» появляется, когда среди выбранного есть `needsOrd`, и разносит текст на «Приложение № 1 — размещение в клубах» и «Приложение № 2 — интернет-размещение (с маркировкой ЕРИД)» (`clubFormats` / `internetFormats`).
  - **Запрос на размещение**: под каждым выбранным форматом — своё поле ссылки (`links: Record<формат, ссылка>`), потому что в кликабельные баннеры вшивается UTM клиента, а в статичные — ссылка под QR-код; ссылка печатается строкой под своим форматом. Даты тоже календарём.
- **Хронология по клиенту** (`src/lib/services/client-timeline.ts`, компонент `advertisers/ClientTimeline.tsx`, типы — `src/lib/timeline.ts`): единая лента в карточке клиента — сделки, встречи из дневника, статусы дня, задачи, версии документов и файлы, оплаты, размещения, ОРД. Восемь типов событий с фильтрами и группировкой по дням; будущее (плановые платежи, сроки, запуск) вынесено в свёрнутый блок «Впереди», чтобы стена планов не закрывала историю. Кнопка «Пересказать историю» → `/api/ai/timeline-summary` (последние 150 событий в промпт). ⚠️ История изменений в базе не пишется (стадии сделки не логируются) — лента строится из дат, которые реально записаны: создание, дата договора, дата оплаты, дата загрузки.

**Заявки с сайта — приём напрямую (вебхук Тильды, 10.2026)**: `POST /api/webhooks/tilda?key=…` (`src/app/api/webhooks/tilda/route.ts` + `src/lib/services/leads-webhook.ts`, разбор тела — `parseWebhookLead` в `leads-parse.ts`, инструкция для человека — `docs/ВЕБХУК_ТИЛЬДА.md`). Сайт на Тильде отдаёт заявку сразу после отправки формы, Google-таблица из цепочки убирается. ⚠️ **Скрипта на сайт не пишем, и это принципиально**: отправка из браузера потребовала бы положить ключ в код страницы, то есть отдать посторонним запись в раздел заявок. Передаёт сервер Тильды, ключ живёт только у нас. ⚠️ Ключ стоит В АДРЕСЕ (`?key=`), потому что своих заголовков Тильда не добавляет — значит, адрес = доступ; выпуск и замена — `npm run leads:key -- --new` (`scripts/webhook-key.ts`, пишет `LEADS_WEBHOOK_SECRET` в `.env`). Сверка ключа — по sha256 через `timingSafeEqual`, иначе длина и скорость ответа подсказывали бы подбирающему. ⚠️ Обработчик отвечает **200 почти всегда** (даже на мусор): для Тильды не-200 = «интеграция сломана», она покажет ошибку и может перестать слать. Отказ только на неверный ключ (401) и на ненастроенный сервер (503); что произошло — в журнале сервера строками `[tilda] created|duplicate|test|empty`. ⚠️ Проверочный запрос Тильды (поле `test`) заявку не создаёт. Тело принимается и формой, и JSON — галочка в Тильде не важна. Поля сопоставляются той же картой, что и колонки таблицы (`FIELD_BY_HEADER`), незнакомые поля и галочки согласий дописываются в текст обращения — то, что написал человек, не теряем. Дубли: точный повтор по `tranid` обновляет карточку, похожая заявка от того же контакта за 15 минут **не перезаписывает** поля, а дописывает новый текст. Канал `site-webhook` добавлен в журнал передач; в Telegram уходит только факт и компания (`notifyNewLead`) — без имени, телефона и почты, роли «Безопасность» не шлём. Новая заявка показывается всплывашкой (`kind: "lead"` в `/api/notifications`). Проверка целиком — `bash scripts/webhook-selftest.sh` (шлёт поддельные заявки от вымышленного человека). ⚠️ Когда вебхук заработал, чтение таблицы выключается строкой `LEADS_SHEET_SYNC="off"` — иначе одно обращение приходит двумя путями; тогда в разделе прячутся кнопки «Обновить» и «Таблица», а `POST /api/leads/sync` отвечает понятным отказом. ⚠️ Вебхуки в `middleware.ts` попадают в `isPublicApi` (проверки происхождения у внешнего запроса быть не может) и имеют свой предел частоты — 600 обращений в час.

5. ✅ **Напарник-картотека**: инструменты вынесены в `src/lib/ai-tools.ts` — читающие (list_my_clients, get_client, search_knowledge, list_inbox_files) и **пишущие** (route_file, create_task, add_daily_status, add_journal_entry, ask_leader). В чат можно прикрепить файл: он падает в «Входящие» (`FileAsset.ownerType="inbox"`, `/api/ai/inbox`), напарник определяет клиента/сделку и раскладывает через route_file — файл сразу виден в карточке сделки и в «Документах». Всё в скоупе сотрудника.

**Что напарник знает о сервисе** (правка после жалобы «плохо ориентируется»): в системный промпт `/api/ai/chat` подставляются два блока. `SERVICE_MAP` (`src/lib/ai-service-map.ts`) — карта сервиса обычным русским языком: разделы и что в них лежит, пять стадий сделки, раскладка документов по 8 подразделам, глоссарий (ЕРИД/ОРД/ДС/УПД), незыблемые правила. Файл рассчитан на чтение человеком — правьте его, когда меняется структура сервиса. `buildAiContext` (`src/lib/ai-context.ts`) — шапка разговора: кто сотрудник, его роль, **сегодняшняя дата по Москве** (без неё напарник не мог посчитать срок «на завтра»), клиенты, сделки по стадиям, блокеры, счётчики задач и неразобранных файлов. Итого системный промпт ≈5,7 КБ.

**Руководство для напарника** (`src/lib/ai-manual.ts`, инструмент `read_manual`): 14 глав, ~22 КБ — как разговаривать, клиенты и сделки, стадии по отдельности, документы и раскладка, разбор входящих файлов, задачи и сроки, деньги/НДС, ОРД, форматы и техтребования, промокоды, встречи, вопросы руководителю, кто за что отвечает, профиль компании. **В системный промпт уходит только оглавление (~0,8 КБ)** — главы напарник вытягивает инструментом по мере надобности: длинный промпт и дорог, и размывает внимание модели. Разделение источников: `read_manual` — как РАБОТАТЬ (порядок, правила), `search_knowledge` — ДАННЫЕ агентства (цифры, реквизиты, размеры). Фактура глав взята из базы знаний отдела и блупринта — не дописывать туда придуманное, напарник считает этот текст истиной. Итого системный промпт ≈7,4 КБ.

**Видно, куда напарник заглядывал**: `aiChat` возвращает `{ text, steps }` — список вызванных инструментов. Под ответом в `/assistant` рисуется «Смотрел: база знаний: «цены» → карточка клиента: МТС», а если инструментов не было — жёлтое предупреждение «Ответил без обращения к данным сервиса». Тот же след печатается в консоль dev-сервера (`[напарник] Имя: «вопрос» → …`). Это диагностика на случай жалоб «плохо ориентируется»: сразу видно, смотрел ли ИИ в данные или сочинял. Описания шагов по-русски — `describeToolStep` в `ai-tools.ts`.

⚠️ **Температура** (`AI_TEMPERATURE`, по умолчанию 0.2): у провайдеров по умолчанию 1.0 — режим свободной беседы, из-за которого напарник выдумывает клиентов и суммы. ⚠️ **`deepseek-reasoner` не поддерживает вызов инструментов** — с ним напарник перестанет видеть данные сервиса; для DeepSeek нужен `deepseek-chat`.

⚠️ **Поиск по базе знаний** (`search_knowledge`) считает в памяти, а не запросом в SQLite: `contains` у SQLite регистрозависим для кириллицы, из-за чего «цены» не находили статью «Цены» и напарник получал «ничего не найдено» на существующий контент. Теперь: нормализация регистра и «ё», отсечение окончаний только у слов от 6 букв (короткие ЕРИД/ОРД/ДС не режем — огрызок ловил мусор), вес заголовка ×3, при промахе отдаётся оглавление базы вместо пустоты.

⚠️ **Регион:** прямые запросы к Anthropic из РФ отвечают `403 Request not allowed` — ключ рабочий, блокируется адрес. Обход: сервер за рубежом, шлюз через `ANTHROPIC_BASE_URL`, или другой провайдер. Ошибки провайдера переводятся в человеческий текст (`aiErrorMessage` в `ai.ts`).

**ИИ-провайдер:** пока Claude (по решению пользователя — «прикрутить к тебе, позже переключим»). Обвязка провайдер-независимая через `ai.ts`. Открытые вопросы на будущее: (1) важна ли data-residency РФ; (2) какой провайдер вместо Claude.

**НЕ сделано (следующие итерации):** RBAC + аудит-лог, S3, realtime на несколько инстансов (сейчас in-memory, для 1 сервера), турнирные инструменты для ИИ-ассистента (пока видит только рекламный контур). **Ждём от пользователя:** `ANTHROPIC_API_KEY` в `.env` для всех ИИ-функций; база знаний коллеги.

⚠️ **Данные:** `npx prisma db seed` ОЧИЩАЕТ базу (демо-набор заново). После первого запуска на реальных данных использовать только `npx prisma db push` (сохраняет данные, добавляет схему).

**Проверка ИИ:** `npm run ai:scan` — показывает, до каких провайдеров достаёт сеть (ключи не нужны). `npm run ai:check` — делает один тестовый запрос к провайдеру и печатает вердикт (что настроено, куда ушёл запрос, что ответил провайдер). Быстрее, чем гадать через интерфейс.

## Безопасность и права

`docs/БЕЗОПАСНОСТЬ.md` — ответ руководству про хранение конфиденциальных данных: где что лежит, разделение по ролям, защита входа, бэкапы. **Пачка правок по требованиям ИБ (10.2026)** — сделано по документу «Требования по безопасности при создании и запуске сервисов»:
- **Ошибки не выдают внутренности** (п. 5.10). Раньше `handleError` отдавал в браузер `err.message` — вместе с путями к файлам и кусками запросов Prisma. Теперь наружу уходит «Что-то пошло не так» + короткий код (напр. `MGN8G5`), а подробности пишутся в журнал сервера той же меткой: `pm2 logs colizeum`, искать `[API error MGN8G5]`. Исключение — `PublicError` (`src/lib/errors.ts`): ошибки, написанные для человека и помогающие починить дело самому («откройте доступ к таблице»). На него переведены все четыре сообщения `leads-sync.ts`. ⚠️ Новые сообщения, которые ДОЛЖНЫ дойти до пользователя, бросайте только через `PublicError`, иначе их подменит общая фраза.
- **Пароль от 12 символов** (п. 5.1) — в `validation.ts` (создание и смена), в формах, в `scripts/set-password.ts` и `reset-passwords.ts`, демо-пароли сида тоже удлинены. ⚠️ На ВХОДЕ длина не проверяется — иначе сотрудники со старыми короткими паролями не смогли бы войти. Менять старые пароли — `npx tsx scripts/reset-passwords.ts`.
- **Заголовки безопасности** (`next.config.mjs`, функция `headers()`): CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`. Главное, что даёт CSP при `'unsafe-inline'`: посторонние домены в список не входят, поэтому чужой скрипт не загрузится, а `frame-ancestors 'none'` не даёт открыть сервис в рамке на чужом сайте. ⚠️ Шрифты тянутся с Google, поэтому `fonts.googleapis.com` и `fonts.gstatic.com` в списке разрешённых — при переходе на свои шрифты эти строки убрать. Проверено: 14 разделов открываются, 4 шрифта грузятся, нарушений нет.
- **Шифрование резервных копий** (п. 6.5): `deploy/backup.sh` шифрует базу и `storage` через `openssl aes-256-cbc -pbkdf2`, файлы получают `.enc`. Пароль — `BACKUP_PASSPHRASE` в `.env`, хранится ОТДЕЛЬНО от сервера. Не задан — копия делается открытой, но скрипт громко предупреждает. Команда восстановления — в шапке скрипта. ⚠️ `grep` пароля в `.env` обязательно с `|| true`: без него `set -e` + `pipefail` роняли весь скрипт, когда строки нет, и копия не делалась вовсе (поймано тестом).

**Что сделано — для человека со стороны (10.2026)** — `docs/ЧТО_СДЕЛАНО.html`, **собирается генератором** `python3 scripts/gen-blueprint.py`. Пять разделов: что это за сервис → «было → стало» тремя таблицами (безопасность по требованиям руководства, удобство по пожеланиям команды, эксплуатация) → весь перечень требований по порядку и с той же нумерацией → что осталось (группируется ПО СТАТУСАМ автоматически, поэтому пункт не может «потеряться») + что осознанно оставлено на серверы компании → как проверить каждое утверждение самому. ⚠️ Статусы здесь НЕ хранятся: источник — перечень, документ читает его и пересобирается. Правите статус — правьте в перечне и пересоберите, иначе два документа разъедутся. ⚠️ Счётчики считаются по тем же восьми разделам, что и в перечне (без разделов 2–3 и чек-листа 8): проверено, сходится в 32/16/11/10/4 = 73.

Главный документ для руководства: 73 требования из их же «Перечня требований», **в том же порядке и с той же нумерацией** (общий перечень → Руслан → Илья 1–10 → Влад/Aspro), у каждого статус и **доказательство — где функция живёт в сервисе и каким файлом сделана**. **Контекст:** собирается **коробочное решение** для переезда с личного сервера пользователя на серверы COLIZEUM. После переезда по ИБ ведёт **Влад**, по технической части — **Илья**, пользователь остаётся автором с частичным доступом. Журналы, логи и доступы будут читать посторонние люди — писать их соответственно.

**Что закрыто 8 октября** (всё проверено на работающем сервисе):
- **Журнал действий** (`AuditLog`, `src/lib/audit.ts`, страница `/leadership/audit`): кто, когда, что открыл, изменил, удалил, выгрузил. ⚠️ **ПДн в журнал не пишутся** — только названия изменённых полей (`changedFields`), без значений; `before`/`after` из первой версии схемы убраны намеренно. Срок хранения 550 дней, чистка (`pruneAudit`) при открытии журнала — отдельного планировщика в сервисе нет.
- **Роль «Безопасность»** (`Security` в `ROLES`, `src/middleware.ts`): ответственный за ИБ видит журнал, доступы и запросы по ПДн и **не видит** клиентов, суммы и бюджет отдела. Под этой ролью работает **Влад Самучев** (должность «СРМ-специалист и ИБ») — он ведёт CRM и готовит перенос на серверы компании. ⚠️ Полные админские права ему сначала выдали по просьбе пользователя, но тут же вернули роль «Безопасность» — его же решением: нужна **админка без коммерции**. Что видит: доступы, журнал действий, запросы по ПДн, сроки хранения; клиентов, сделок и денег не видит. ⚠️ Два блока на «Команде» закрыты ролью `Owner` и ему НЕ видны — служебные ключи API и привязка Telegram. Ключи дают доступ к данным клиентов через API, поэтому отдавать их тому, кто клиентов не видит, нельзя; если понадобится, ключи выпускает админ. Сделано белым списком в middleware: страницы вне списка уводят на журнал, API отдаёт 403. Дать Владу `Director` было нельзя — это открыло бы всю коммерцию, против требования 5.2.
- **Второй фактор** (`src/lib/totp.ts` — TOTP на `node:crypto`, без библиотек; `/api/users/[id]/totp`, окно из меню профиля): QR → подтверждение кодом → 8 запасных кодов, в базе только их bcrypt-хэши. Вход стал двухшаговым (`pending`-токен на 5 минут, сам по себе доступа не даёт).
- **Согласие с документами** (`ConsentRecord`, `src/components/legal/ConsentGate.tsx`): при первом входе экран с тремя **пустыми** галочками, кнопка не нажимается, пока не отмечены все. Версия документа — sha256 его текста (12 символов): поправили политику → версия сменилась → сервис просит принять заново. Правило 4.2 просит именно отдельную не-предотмеченную галочку, акцепта «по факту входа» недостаточно.
- **Права человека на свои данные** (`src/lib/services/person-data.ts`, `/leadership/privacy`): найти всё, что есть о человеке, и удалить. Контакты удаляются, заявки с сайта и дневник обезличиваются, работники и журнал остаются — это объясняется на экране.
- **Тревоги** (`src/lib/services/security-alerts.ts`): семь событий сервис сам шлёт ответственному за ИБ (`notifySecurity` → Telegram + всплывашка) и показывает наверху журнала — подбор пароля, вход с незнакомого адреса, вход в 23:00–07:00 МСК, отключение второго фактора, смена роли, сброс пароля админом, выгрузка клиентов всего отдела. ⚠️ Один и тот же сигнал с того же адреса глушится на 6 часов, иначе перебор на тысячу попыток = тысяча сообщений и бот в mute. ⚠️ Первый вход нового сотрудника тревогой не считается.
- **Недоступность** — `deploy/monitor.sh` по cron раз в 5 минут (приложение, pm2, домен снаружи, диск, сертификат, свежесть копий) + сообщение о восстановлении. Отдельным скриптом снаружи намеренно: упавшее приложение само бы ничего не отправило. Адресат — `ALERT_TELEGRAM_CHAT_ID`.
- **Проверка загружаемых файлов** (`src/lib/upload-rules.ts`): белый список расширений и 50 МБ, подключено во все точки загрузки.
- **Поля синхронизации с Aspro** (`asproId`/`syncEnabled`/`syncStatus`/`asproSyncedAt` в 6 моделях) — задел под требования Влада.

## Боевой запуск на домене

Инструкция — `docs/ДЕПЛОЙ.md` (писалась для непрограммиста, по шагам); `docs/DEPLOY.md` — её прежняя версия, оставлена из-за ссылок в `deploy/setup-server.sh` и `deploy/healthcheck.sh`, сверху стоит шапка «актуальная другая». Схема: обычный VPS (Ubuntu 24.04) + Node 22 + pm2 + nginx + certbot. **Не serverless**: SQLite, локальное хранилище файлов и in-memory SSE требуют постоянного диска и одного процесса.

**Действующий сервер — `/root/Colizeum__CRM`** (не `/var/www/colizeum`, как в инструкции по первому запуску: первый сервер поднимали в домашнюю папку root). Ветка сайта — `claude/deploy-site-timeweb-domain-2m5dhk`, она же по умолчанию в `scripts/deploy.sh`.

**Обновление — один путь, `scripts/deploy.sh`**: проверки сервера (диск, память под сборку, Node, обязательные ключи в `.env`) → показ, что приедет → резервная копия **с проверкой, что она создалась** → запись текущей версии в `.deploy-prev` → код/зависимости/схема/сборка/перезапуск → проверка, что сайт отвечает. Сид намеренно не входит. Спутники: `npm run release:notes` (что приедет, ничего не меняет), `npm run deploy:check` (= `--dry`), `scripts/rollback.sh` (вернуть прежний код; база не трогается), `deploy/healthcheck.sh` (отчёт по серверу, запускается в конце деплоя).

⚠️ **Дубли инфраструктуры убраны, и это было не косметикой**: `deploy/update.sh` и `scripts/backup.sh` стали переходниками. Прежде это были вторые, самостоятельные сценарии: `update.sh` делал `bash deploy/backup.sh || echo "(пропущено)"` — то есть обновлял сервис БЕЗ копии при любой заминке, и тянул код через `git pull` без ветки; `scripts/backup.sh` не шифровал копии (против требования 6.5) и складывал их в `../colizeum-backups`, тогда как сторож `deploy/monitor.sh` и инструкция смотрят `/var/backups/colizeum` — тревога «копия устарела» могла висеть при живых копиях. Настоящие реализации: `deploy/backup.sh` и `scripts/deploy.sh`.

⚠️ **Ветка по умолчанию в `deploy.sh` — грабли, на которые уже наступили**: там стояла августовская ветка, а ниже `git reset --hard`. Запуск без имени ветки откатил бы сайт на 93 коммита. Теперь ветка рабочая, а перед сбросом считается, сколько правок потеряется, и при откате назад скрипт требует слова «да» (или `FORCE_ROLLBACK=1`).

⚠️ **`prisma db push` на боевой базе**: обязательный столбец без `@default` в непустую таблицу SQLite добавить нельзя — push встаёт, а Prisma в подсказке предлагает `--force-reset`, то есть стереть базу. Так было с `Invoice.updatedAt` (поймано на копии боевой схемы до обновления, поле получило `@default(now())`). Удаление столбца с данными требует `--accept-data-loss` — у нас это осознанный случай `AuditLog.before/after`. `deploy.sh` ловит оба отказа и объясняет их словами, прямо запрещая `--force-reset`.

**Что приедет на сервер и что это значит для людей** — `docs/ЧТО_НОВОГО.md`: правки коллег таблицей И-1…И-13, безопасность по пунктам перечня, задел под Aspro, инфраструктура, «что изменится для людей» (экран согласия, пять стадий, пароли, второй фактор) и отдельный список **что осознанно оставлено на серверы компании** (webhook'и, сама синхронизация с Aspro, PostgreSQL, S3, realtime на нескольких инстансах, SSO, сроки хранения, где живёт ИИ). В nginx критичны два места: `client_max_body_size 50m` (иначе не грузятся документы) и отдельный блок для `/api/chat/stream` с `proxy_buffering off` (иначе рвётся мгновенный чат).

**Скорость.** Замер (`deploy/perf-check.sh домен.ru`) показал: сам рендер страниц 12–37 мс на демо-данных — код не тормозит, тормозит окружение. Четыре места, где это лечится: (1) **SQLite в WAL** — по умолчанию база живёт в `journal_mode=delete`, где любая запись блокирует ВСЕХ читателей; режим включается один раз при старте (`src/lib/prisma.ts`, хранится в самом файле базы, переживает перезапуски). ⚠️ `backup.sh` из-за WAL копирует ещё и `-wal`, если `sqlite3` не установлен. (2) **HTTP/2 в nginx** — без него браузер тянет ~10 файлов страницы по очереди; включается параметром в строке, которую дописывает certbot: `listen 443 ssl http2;`. ⚠️ Отдельная директива `http2 on;` есть только с nginx 1.25, а в Ubuntu 24.04 идёт 1.24 — с ней сервер не стартует. (3) **`staleTimes` в `next.config.mjs`** — страница, открытая меньше 15 с назад, при возврате берётся из памяти браузера; 15 с намеренно мало, чтобы устаревших данных на экране не было. (4) **Мессенджер** больше не опрашивает сервер каждые 4 с поверх живого SSE-соединения: пока связь есть — раз в 20 с, во вкладке в фоне не опрашивает совсем.

## Архитектура

- **Монолит**: Next.js 15 (App Router) + TypeScript + Tailwind.
- **БД/ORM**: Prisma + SQLite (dev) → PostgreSQL (prod). Все сущности и связи — `prisma/schema.prisma`. Enum'ы хранятся строками, источник значений — `src/lib/enums.ts`, валидация Zod — `src/lib/validation.ts`.
- **Файлы**: `StorageProvider` (`src/lib/storage/`), dev — локальный диск `./storage`; в БД только метаданные (sha256, версии). Файлы ОРД — ключи `ord/{id}/{kind}/…`.
- **Auth**: cookie-сессия (JWT `jose`, httpOnly), bcrypt, 2 аккаунта. `src/lib/auth.ts`.
- **Слои**: страницы (server components, Prisma напрямую) → клиентские островки (`src/components/**`) → API-роуты (`src/app/api/**`, Zod, `{ error: { code, message } }`) → сервисы (`src/lib/services/**`).
- **Инварианты стадий** — `src/lib/services/deal-stage.ts`: предупреждения → 409 → подтверждение `confirm=true`.

**Стадии сделки — ПЯТЬ, а не девять (правка 10.2026, пункт коллег И-6).** `Лид → Договор → Оплата → Размещение → Закрытие` (`DEAL_STAGES` + `STAGE_HINTS` в `enums.ts`). Было девять: половина описывала не «где сделка», а какую бумагу готовят. ⚠️ **«Оплата» осталась отдельным шагом не для красоты** — на неё опирается незыблемое правило «размещение стартует только после предоплаты»; уберёте её из воронки, и предупреждение при переходе станет неформулируемым. Перевод старых записей — `npm run stages:migrate` (прежнее название дописывается в примечание сделки, ничего не теряется). ⚠️ Воронка в обзоре отдела (`DeptFunnel`) больше не держит свой список групп — строится прямо по `DEAL_STAGES`, иначе два списка разъезжаются. ⚠️ Порог «перепрыга стадий» в `deal-stage.ts` снижен с 3 до 2: шагов вдвое меньше. Полоса стадий в карточке сделки — явная линейка со стрелками, подписями и подсказками; отмеченные «не относится к этой сделке» (`Deal.skippedStages`) показываются зачёркнуто.

## Телефон

Сервис открывается с телефона наравне с компьютером. Ключевое, что было сломано: в `(app)/layout.tsx` стоял `flex` без брейкпоинта, поэтому мобильная шапка становилась соседней КОЛОНКОЙ рядом с содержимым — логотип сжимался в полоску слева, страница в остаток экрана. Теперь `md:flex`.

Что есть: **нижняя панель** (`src/components/MobileTabs.tsx`) — Сегодня / Задачи / главный раздел направления / Чат / Ещё; «Ещё» открывает ту же выдвижную шторку событием `colizeum:open-menu`, которое слушает `Sidebar`. В мобильной шапке — название текущего раздела (иначе непонятно, где ты). Поля ввода на телефоне 16 px, иначе Safari сам увеличивает страницу и обратно не отъезжает. `overflow-wrap: break-word` на `body` — длинная почта или ссылка раздвигала страницу вширь.

⚠️ Дети grid и flex по умолчанию не сжимаются уже своего содержимого: длинное название клиента растягивало колонку, а с ней всю страницу. Там, где внутри `truncate`, родителю нужен `min-w-0` — так починены карточки клиентов, колонки «Сегодня» и «Дневника».

Проверка: `node scripts/mobile-check.mjs` (нужен работающий `npm run dev`, пароль — в `CHECK_PASSWORD`) гоняет 15 разделов **и две карточки — сделки и клиента** в Chromium с профилем iPhone 13, сравнивая ширину содержимого с шириной экрана. Всё укладывается. Playwright в зависимости проекта намеренно не входит (тянет браузеры на сотни мегабайт) — скрипт сам скажет, что поставить.

⚠️ Карточки в проверку добавлены не случайно: пока смотрели только списки, проверка показывала «все 15 укладываются», а карточка сделки на телефоне разъезжалась на 76 px, карточка клиента — на 99 px. Причина — та же, что в абзаце выше: колонки внутри `grid gap-6 lg:grid-cols-3` не имели `min-w-0`, поэтому раздувались до содержимого самой широкой карточки (реквизиты, суммы с НДС, строки хронологии). Самые плотные страницы сервиса — именно карточки, их и надо проверять в первую очередь.

## Юзабилити-правка 10.2026 («чтобы дышало»)

Разбор делался по живым экранам, не по памяти: `node scripts/scale-preview.mjs /dashboard 16 17 18` снимает один экран в трёх масштабах — спорить о размере шрифта словами бесполезно.

- **Масштаб интерфейса — одна строка**: `html { font-size: 17px }` в `globals.css`. Всё в Tailwind считается в rem, поэтому за базой тянутся отступы, высоты полей и радиусы. 16 → 17 (+6 %) по замечанию «мелко»; 18 съедает первый экран. ⚠️ После правки масштаба ОБЯЗАТЕЛЬНО `npm run mobile:check`: первая же попытка дала переполнение `/dashboard` на 10 px (шапка «Статуса дня» с двумя кнопками не переносилась) — лечится `flex-wrap`.
- **Низ бокового меню** (`Sidebar.tsx`): блок профиля получил `shrink-0`, правовые ссылки — одна строка короткими словами (`LEGAL_TINY`), полные названия в подсказке. Раньше три длинные ссылки обрезались нижним краем экрана, и при увеличении масштаба это стало заметно.
- **Напоминание про второй фактор закрывается** — `src/components/ui/DismissibleNotice.tsx` (отметка в `localStorage`, ключ `colizeum_notice_<id>`). Оно висело на КАЖДОЙ странице и съедало верх экрана. ⚠️ Закрыть ≠ сделать: пока второй фактор не включён, у аватарки в `UserMenu` горит точка (`twoFactorPending` прокидывается из `(app)/layout.tsx` через `Sidebar`).

Пустая карточка «Отправленные вопросы появятся здесь» убрана, «Решать нечего» осталось только у руководителя — две надписи об одном шли подряд. Форма статуса дня свёрнута под кнопку «+ Записать» (`DailyStatusPanel`): заполняют её раз в день, а место она занимала всегда.

Пустые колонки сжимаются до `w-40`, поэтому все пять стадий помещаются в экран без листания стрелками.

Поля показателей встречи появляются ТОЛЬКО после разбора или по ссылке «заполнить руками»: пустая анкета на девять полей отпугивала сильнее, чем помогала.

**Второй заход (тишина интерфейса и таблицы):**
- **Карточки больше не прыгают**: у `.card-hover` убраны подъём на 3 px, жёлтая кромка и тень — осталась смена фона и границы. На одной карточке эффект красив, на списке из двадцати курсор по экрану превращался в рябь. По той же причине пункт меню не съезжает вбок, а значок не раздувается.
- **Меню сворачивается по группам** (`Sidebar.tsx`): заголовок группы — кнопка, состояние в `localStorage` (`colizeum_nav_collapsed`), по умолчанию свёрнута «Соответствие» (`DEFAULT_COLLAPSED`). ⚠️ Группа с ОТКРЫТОЙ страницей не сворачивается никогда — иначе человек не видит, где находится. Журнал действий, запросы по ПДн и сроки хранения рядовому менеджеру не нужны каждый день, а висели в меню постоянно.
- **«Клиенты»**: с плиток убрано «Удалить» (шесть карточек = шесть кнопок удаления рядом с правкой) — удаление переехало в карточку клиента под «Ещё», рядом с «Архивом». Бейдж типа показывается, только если тип НЕ «Рекламодатель» (он стоял на каждой плитке и ничего не различал). Нулевые счётчики скрыты, остальные склоняются (`plural` в `src/lib/format.ts`): «1 сделка», «2 сделки», «5 сделок».
- **«Входящие с сайта»**: колонки «Кто обратился» и «Контакт» объединены в одну. Раньше они делили ширину с текстом обращения, и телефон переносился на две строки, а почта обрывалась посреди слова; теперь телефон `whitespace-nowrap`, почта `truncate` с полным значением в подсказке.

**Третий заход (отклик, размеры, оплаты):**
- **Отклик вернули, но светом, а не движением**: `.card-hover` снова даёт фирменную жёлтую кромку и мягкую тень при наведении, подъём на 3 px не вернулся — именно он заставлял список дёргаться. У `.btn-ghost` своя подсветка: «живость» не только у жёлтых кнопок.
- **Мелкие кнопки увеличены** (замечание «мелкие и неочевидные»): `.btn` ≈40 px в высоту (`py-2.5`), `.btn-sm` — `text-sm` и ≈34 px вместо `text-xs`/28, `.btn-icon` 36 → 40 px, корзина `DeleteButton` 32 → 40 px, значки в `FileCell` — кликабельные квадраты 32 px вместо иконки 13 px, имя файла `text-sm`. ⚠️ Кнопка удаления файла больше НЕ прячется до наведения (`opacity-0 group-hover`): невидимую кнопку не находят.
- **«Разложить оплату»** (`AddPaymentModal` в `PaymentCalendar.tsx`) вместо прежней формы планового платежа. Проблема была не в форме, а в том, что арифметику человек держал в голове: сколько по договору, сколько уже разложено, сколько осталось — и регулярно раскладывал БОЛЬШЕ суммы договора (экран ругался, сходилось руками). Теперь окно: выбрал сделку → плашка «Договор / Разложено / Осталось» и кнопка **«Взять весь остаток»** → два способа крупными кнопками («Одним платежом» / «По месяцам» + счётчик месяцев) → **предпросмотр** «6 платежей с окт 26 по мар 27 — по 3 538 000 ₽, всего 21 228 000 ₽ с НДС». Остаток от деления уходит в последний месяц, иначе сумма частей не сходится с введённой. ⚠️ Платёж теперь пишется с `dealId` — раньше поле не заполнялось вовсе, и сверка по сделке была невозможна. ⚠️ Суммы плановых платежей лежат ЧИСТЫМИ, поэтому остаток считается в чистых, а на экране показывается с НДС.
- ⚠️ **Дыра в `POST /api/planned-payments`**: проверка владельца стояла на правке и удалении, а на создании её не было — зная идентификатор чужого клиента, можно было завести платёж в его календарь. Добавлены `guardAdvertiser`/`guardDeal` и проверка, что сделка принадлежит тому же клиенту. Тот же класс ошибки, что ловили в маркировке (И-9).

**Четвёртый заход — схемы оплаты и график (10.2026).** Окно «Разложить оплату» из формы на одну сумму стало **конструктором плана**: сверху полоса остатка, ниже строки плана, под ними картинка. Порядок работы — «заполняем, пока остаток не 0».
- **Схемы оплаты** — те, которыми работают в агентстве (список дал пользователь, не выдумывать): **100 % предоплата**, **50 % / 50 %** (постоплата по умолчанию встаёт в последний месяц срока услуг, месяц правится в строке), **равными по месяцам**, **своя схема**. Схема — это заготовка строк, а не сущность в базе: после нажатия любую строку правят руками. Поле «срок услуг, мес.» общее для схем: от него считается и число равных частей, и месяц постоплаты.
- **Остаток — главный прибор окна**: «Распределено X из Y», полоса, «Остаток 0 — сходится» зелёным. Пока остаток больше нуля, рядом стоят две кнопки: «+ Платёж на остаток в <месяц>» и «разбить остаток на N мес.» — ими и собирается смешанный случай пользователя (6 месяцев: 50 % предоплатой, остальные 50 % тремя равными частями). Проверено живьём: 8 700 000 + 2 900 000 × 3 = 17 400 000 чистыми, «из 21 228 000 ₽» в календаре сходится ровно.
- ⚠️ План сохраняется построчно, подпись строки уходит в `note` платежа («Предоплата 50 %», «Платёж 2 из 3») — раньше на месте подписи стояло служебное «часть 2 из 3».
- **График оплат** (`src/components/finances/PaymentChart.tsx`) — столбики по месяцам над календарём и такой же предпросмотр внутри окна **до сохранения**. Таблица отвечает «кто и когда платит», график — «ровно ли лежат деньги по месяцам»; это разные вопросы, поэтому оба вида оставлены. Без библиотек: столбик — это div с процентной высотой (recharts утянул бы сотни килобайт ради одной картинки).
- ⚠️ Цвета графика (оплачено `#059669` / ждём `#F59E0B` / просрочено `#EF4444`) проверены валидатором на различимость при дальтонизме: ΔE 13,0 (протанопия) при пороге 8, 19,8 при обычном зрении при пороге 15, контраст с фоном выше 3:1. Жёлтый по светлоте выходит за полосу для категориальных палитр — это свойство жёлтого, поэтому цвет НЕ единственный ключ: у каждого ряда подпись в легенде и в подсказке, а под графиком та же таблица цифрами. Меняете цвета — прогоните заново, не на глаз.
- **Работа с месяцем «ГГГГ-ММ» вынесена в `src/lib/month.ts`** (`monthLabel`, `shiftMonthStr`, `monthRange`, `compactMoney`): эти функции были скопированы в календаре и в окне, третья копия в графике точно разъехалась бы с первыми двумя.

## Разгрузка интерфейса по итогам UX-аудита (10.2026)

Аудит — `docs/АУДИТ_UX.md` (22 живых экрана, разбор по вкладкам). Правки идут
волнами; решения пользователя по каждому пункту записаны там же.

**Волна 1 — тишина и мелочи.**
- ⚠️ **Удаление больше не красное в покое.** `DeleteButton` (вариант «icon») —
  нейтральная серая иконка, краснеет только под курсором и при фокусе. Причина:
  на доске задач красная корзина читалась громче названия задачи. Удаление при
  этом НЕ прячется до наведения — невидимую кнопку не находят (проверено
  раньше). Тот же вид у удаления канала в мессенджере и файла в базе знаний.
- **Две плашки убраны с экранов**: полоса «Включите вход по коду» висела на
  каждой странице (теперь подсвеченный пункт в меню профиля + точка на
  аватарке), красная ссылка «Данные могли утечь» накладывалась на правовые
  ссылки внизу меню (теперь пункт в меню профиля — он есть у всех ролей).
- **Ширина страницы 1280 → 1600** (`(app)/layout.tsx`): на рабочих мониторах
  контент упирался в середину экрана.
- **Заголовки карточек, повторявшие название страницы, убраны** (оплаты,
  размещения): два одинаковых заголовка подряд съедали первый экран.
- ⚠️ **Дата по-русски — свой компонент** `src/components/ui/DateInput.tsx`
  (дд.мм.гггг + кнопка-календарик, наружу отдаёт ISO). Системное
  `<input type="date">` берёт формат из настроек БРАУЗЕРА, а не из языка
  страницы, и показывало `mm/dd/yyyy`; атрибутом это не чинится. Заменено во
  всех 33 местах сервиса, проверено живьём на создании отсутствия.
- Мелочи: склонения через `plural` в «Передаче дел»; в промокодах главная цифра
  — сумма партии (`formatNumber` в format.ts); в ОРД колонка действий получила

  миграции `[стадия до перевода: …]` (`cleanNotes`); раздел назван
  «ИИ-ассистент» и в меню, и на странице.

**Волна 4 — одна кнопка ИИ и файлы сделки.**

  («Разобрать расшифровку» в дневнике, «Собрать саммари» в передаче дел)
  намеренно остались на месте: они часть сценария, а не отдельная способность.
- **Карточка сделки: три зоны загрузки → один блок «Файлы сделки»** с тремя
  корзинами (Документы / Медиапланы и КП / Счета и платёжки) — тот же приём,
  что в «Документах». Секция «Документы с версиями» показывается, только если
  версии есть; у медиапланов и счетов пустое состояние стало строкой с
  подсказкой, в какую корзину класть файл. Страница короче примерно на 400 px.

**Правки по `/impeccable audit` (P1, 10.2026).** Внешний аудит скилла + замеры
на живых страницах дали 14/20 и два настоящих нарушения доступности:
- ⚠️ **`text-ink-600` больше не используется для текста** (37 мест → `ink-500`).
  `#3A3A3B` на карточке даёт контраст **1,5:1** при норме 4,5:1 — подписи оси
  графика, имена файлов, «пусто» в колонках и `⌘K` физически не читались.
  `ink-500` даёт 5,1:1. ⚠️ ink-600 остаётся только для границ и разделителей,
  это записано в `DESIGN.md`.
- ⚠️ **Цели нажатия доведены до минимума WCAG 2.2 (24×24)**: заголовки групп
  меню были полосой 246×**15 px** (стало 28), правовые ссылки внизу — 13 px
  (стало 25, ряд умеет переноситься), ссылки-стрелки «→» на «Сегодня» и в
  карточке клиента стали словами («Все записи →», 109×30).
- Повторный замер: случаев низкого контраста 0 (оставшиеся два — ложные, это
  тёмный текст на жёлтом градиенте кнопки, настоящий контраст 14,5:1), все
  цели ≥25 px.

**P2 того же аудита (10.2026).**
- ⚠️ **Полосы прогресса анимируются `transform`, а не `width`** (воронка отдела,
  освоение бюджета, остаток в «Разложить оплату»): ширина — свойство раскладки,
  браузер пересчитывает страницу каждый кадр. Приём: полоса шириной во весь
  трек сдвигается влево на недостающий процент (`translateX(-${100 - pct}%)`), а
  трек с `overflow-hidden` её обрезает. ⚠️ Именно сдвиг, а не `scaleX`: масштаб
  растянул бы и скругление торца. Проверено живьём — 0 % и 100 % дают ровно
  пустую и ровно полную полосу.
- **Прямые цвета статусов убраны в словарь** `src/lib/ui-tokens.ts`
  (`sideStyle()` — чья сторона, `RECURRING_NOTE`, `CREATIVE_STATUS_STYLES`,
  `TIMELINE_ACCENT`). Раньше один и тот же «ждём клиента» был написан разными
  оттенками в шести файлах.
- **Скелетон вместо слова «Загрузка…»** в мессенджере: силуэт будущих пузырей
  (класс `.skeleton`, тот же, что на `(app)/loading.tsx`).
- ⚠️ **Месяц тоже стал русским** — `src/components/ui/MonthInput.tsx` (два
  списка: «Октябрь» + «2026»). `<input type="month">` рисует браузер и
  подписывает месяц на ЕГО языке: в «Разложить оплату» стояло «October 2026».
  Та же причина, по которой раньше завели `DateInput`; наружу по-прежнему
  уходит «ГГГГ-ММ», API не менялся. Оставшийся браузерный формат — `type="time"`
  в дневнике (в англоязычном браузере даст 12-часовой вид с AM/PM); дату это не
  искажает, поэтому не трогали.

**P3 того же аудита (10.2026) — движение и шум.**
- ⚠️ **Пружина убрана из трёх ускорений** (`globals.css`): было
  `cubic-bezier(0.34, 1.56, 0.64, 1)` — коэффициент больше единицы означает
  ПЕРЕЛЁТ: кнопка, метка в меню и окно на миг проскакивали мимо конечного
  положения и возвращались. На одной кнопке это мило, на рабочем экране с
  десятком кнопок — дребезг. Теперь везде `cubic-bezier(0.22, 1, 0.36, 1)` —
  то же затухание, что у появления страницы.
- **Затемнение под окнами — графит, а не чистый чёрный** (`bg-black/70` →
  `bg-ink-950/75` в модалке, поиске и мобильной шторке): на тёмной теме чистый
  чёрный выглядит провалом, а не слоем.
- ⚠️ **Цветной торец слева в хронологии клиента убран**: тип события и так
  написан словом и показан значком, а девять разных цветов превращали ленту в
  радугу. Словарь `TIMELINE_ACCENT` удалён за ненадобностью.
- Заголовки колонок доски задач и канбана сделок стали `h2` (были жирный
  `span`) — экранный диктор теперь умеет переходить по колонкам; вид не
  изменился. Аватарки получили `loading="lazy"`.

## Дизайн-скиллы (поставлены 10.2026 по просьбе пользователя)

В `.claude/skills/` лежат три сторонних скилла — они подхватываются автоматически
в любой сессии (и в облачной, и локально), вызываются по имени через `/`:

| Скилл | Для чего | Лицензия |
|---|---|---|
| `impeccable` | дизайн и аудит интерфейса: вёрстка, иерархия, типографика, цвет, доступность, анти-паттерны. Подкоманды `craft / shape / audit / polish / quieter / typeset / live` | Apache 2.0, Paul Bakaus; основан на frontend-design от Anthropic (`NOTICE.md` внутри) |
| `design-taste-frontend` (папка `.claude/skills/design-taste-frontend`, бывш. taste-skill) | арт-дирекшн: как уйти от «среднего сайта, сделанного моделью»; библиотека направлений по 247 разобранным сайтам, инспектор в реальном браузере | MIT, Leonxlnx |
| `motion-framer` | анимации на Motion / Framer Motion для React | MIT, Claude Skills Project |

⚠️ **Чего ждать от каждого.** `impeccable` требует контекст проекта и сам его
читает — для этого в корне лежат **`PRODUCT.md`** (кто пользуется, назначение,
анти-референсы, принципы) и **`DESIGN.md`** (палитра, шрифты, компоненты,
движение). Оба файла — выжимка из этого CLAUDE.md и кода, ничего выдуманного;
правьте их вместе с кодом, иначе скилл будет советовать мимо.
`design-taste-frontend` заточен под ЛЕНДИНГИ и публичные страницы (для рабочих
экранов у него отдельный режим «app screens»); его скриптам нужен браузер —
`CHROME_PATH=/opt/pw-browsers/chromium`. `motion-framer` предлагает библиотеку
`framer-motion`, которой в проекте НЕТ: анимации сделаны на CSS и Tailwind,
поэтому его советы — к обдумыванию, а не к автоматической установке
зависимости.

⚠️ Скиллы — это инструкции, которые управляют поведением ИИ. Содержимое
проверено при установке (обычный markdown + скрипты на Node, ничего постороннего),
но при обновлении из их репозиториев проверяйте заново. Исходники:
`julesfleche/impeccable-skill`, `Leonxlnx/taste-skill`,
`freshtechbro/claudedesignskills` (из последнего взят только `motion-framer`).
